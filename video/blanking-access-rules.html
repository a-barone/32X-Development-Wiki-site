V-blank and H-blank access rules

The 32X video chip reads its registers and shows its picture on a fixed schedule: a line is drawn, then comes a short horizontal blank, and after the last picture line a longer vertical blank. Some resources may only be touched at certain times in that schedule. This page lists those rules by time of the frame. You need it to decide when to swap buffers, write the palette or change the display mode without glitches.

Summary#

  • Drawing buffer. The CPU side that owns FM can write the frame buffer being drawn at any time. A buffer swap only happens in V-blankDOC[S001-11-swap].
  • Palette. In packed pixel and run-length modes the palette is reachable only in H-blank and V-blankDOC[S001-11-pal].
  • Mode changes. Bitmap mode, screen shift and priority can be written at any time and take effect from the next lineDOC[S001-11-next].
  • Beam position. VBLK and HBLK (bits 15 and 14 of the frame buffer control register) show where the beam is. The register is described on Frame buffer and line table.

Register latch#

The VDP copies its registers once per line, at a fixed point after horizontal blank begins. This is called the latch.

  • The manual's latch rule. A register set within interval C (H-blank to latch) takes effect on line n. One set within "interval D" takes effect on line n + 1DOC[S001-11-latchrule].
    • The manual's latch timing figure (Figure 3.17) draws interval D from one latch point to the next, with no length givenDOC[S005-11-figD].
    • Sega asks that CPU register writes not overlap the latch pointDOC[S001-11-overlap].
  • In the emulator. Tested on the jgenesis emulator, a screen-shift write made right at the start of an H-blank takes effect on line 100, and the same write delayed 150 loops takes effect on line 101. See the emulator section below.
  • Sega's own mid-frame mode switch is Mars Check's "3 MODE DISPLAY" test, run from the 68000.
    • It is driven by the Mega Drive VDP's H interrupt. The handler counts lines.
    • The main loop writes the bitmap mode byte once the count reaches lines $10, $50, $90 and $D0, without polling HBLKCODE[S206-hint].
    • In the GenDev forum thread "Mars Check Program results for Kega Fusion v3.61" (2009), the forum member TascoDLX relays reports that the program passes all of its tests on real hardwareCOMM[S115-11-mcpass].

Techniques#

  • The 32XDK wiki, the community-written wiki for 32X developers on GitHub, advises on its "Video" page to update the palette from the V-blank handler, and only while the SH-2 owns the VDPCOMM[S012-11-vbi].
  • Mode, shift and priority changes per line let one frame mix settings (see Video modes (packed pixel, direct colour, run-length)).

Pitfalls#

Palette writes near the end of blanking are lost silently. In packed pixel and run-length modes, the VDP ignores any palette read or write made in the last 1 us before PEN (the palette access flag) changes from 1 to 0DOC[S001-11-1us]. Finish palette updates earlier in the blank.

  • d32xr, the GitHub source of Doom 32X Resurrection, writes its palette from the V-blank interrupt handler, at the start of the blank, well away from the endCODE[S097-11-vbi].

Swap timing. After writing FS, the buffer about to be drawn is still on display until the swap happens. Wait as the table says. Lusid Dreams, mic's SID music player for the 32X, writes FS and then spins until the FS read-back changesCODE[S087-11-fs].

Tested on the jgenesis emulator#

These results come from the jgenesis emulator (version 0.14.1). Nobody has confirmed them on a real 32X yet.

  • Test set-up. Every frame the SH-2 counts 100 HBLK rising edges after V-blank. It then writes SFT = 1 at once or after a 150-iteration delay loop. A pixel ramp on lines 90 to 130 shows where the shift starts.
  • Result. The first shifted line is 100 for the immediate writeEMU:jgenesis core 0.14.1[T213-100] and 101 for the delayed writeEMU:jgenesis core 0.14.1[T214-101].
  • Line 90 stays unshifted and line 130 shifted in both runs.
  • The emulator models a latch point inside the H-blank, as the manual describes.
