Glossary

Terms used across this reference, with a short plain definition and the page that covers each one. The definitions are orientation only: the facts (addresses, bits, timings) live on the linked pages with their citations. Where a term is defined by Sega's own manual, the definition follows the manual and is marked like any other statement.

Processors and bus#

termmeaningsee
SH-2the 32-bit RISC (simplified instruction set) processor from Hitachi that the 32X uses; the 32X carries two of themDOC[S001-g-sh2]The SH-2 on the 32X
Master SH-2 / Slave SH-2the two SH-2 CPUs. "Master" and "slave" are about bus priority: the master takes the bus normally, and the slave gets it with the master's permissionDOC[S001-g-master]Dual-CPU synchronisation on the 32X
68000 side / SH-2 sidethe two CPUs' different addresses for the same 32X register or memoryMemory map
cachea small, fast memory between the CPU and the slower main memory; data found there is a "cache hit", data not found is a "cache miss"DOC[S001-g-cache]The SH-2 on the 32X
cache-throughthe SH-2 address view that bypasses the cache. Sega requires it for the system and VDP registers, because other processors can change those and the cache could not followDOC[S001-g-through]Memory map
SDRAMsynchronous dynamic RAM, the 32X's main memory; unlike plain DRAM it holds an address internally and transfers in step with a clockDOC[S001-g-sdram]Timings and clocks
DMAdirect memory access: data moves between memory and devices, or between memories, without the CPU doing the copyingDOC[S001-g-dma]DMA (68000 to SH-2 FIFO, SH-2 DMAC)
FIFOfirst-in first-out: a buffer that hands data out in the order it came inDOC[S001-g-fifo]DMA (68000 to SH-2 FIFO, SH-2 DMAC)
DREQthe DMA request circuit through which the 68000 sends data to the SH-2 side DMA controllerDOC[S001-g-dreq]DMA (68000 to SH-2 FIFO, SH-2 DMAC)
communication portsregisters that pass data in both directions between the 68000 and the SH-2sDOC[S001-g-comm]Communication ports
bus cycle, wait statea bus cycle is one CPU access to a device: at least 4 clocks on the 68000 and 2 on an SH-2. Each wait state adds one clock to itDOC[S001-g-wait]Memory map
master clock (fosc, Mck)the single crystal clock all 32X clocks are divided from; one period of it is one Mck. A 68000 cycle is 7 Mck and an SH-2 cycle a third of thatDOC[S001-g-mck]Timings and clocks
DMACthe DMA controller built into each SH-2, with two channelsDOC[S003-g-dmac]SH-2 on-chip peripherals on the 32X

Control bits and interrupts#

termmeaningsee
ADENthe "address enable" bit. Setting it to 1 maps the 32X into the 68000's address space; Sega's start-up program does this before it initializes the hardwareDOC[S001-g-aden]Boot, security and ROM headers
FMthe "VDP access authorization" bit. It must be 0 before the Mega Drive can use the frame buffer, overwrite image, VDP registers or paletteDOC[S001-g-fm]Bus arbitration
RVthe "ROM to VRAM DMA" bit. Only when it is 0 can an SH-2 read the cartridge ROMDOC[S001-g-rv]Bus arbitration
CMD interruptthe command interrupt: the 68000 raises it on the master or the slave SH-2 by setting the INTM or INTS bitDOC[S001-g-cmd]Interrupts
VRES interruptthe interrupt caused by pressing the Mega Drive reset button; it too must be clearedDOC[S001-g-vres]Interrupts
FRTthe SH-2's free-running timer. Sega's manual restricts its use by programsDOC[S001-g-frt], because its output drives part of the 32X interrupt fixSH-2 on-chip peripherals on the 32X
68Sthe DREQ control bit that starts a 68000-to-SH-2 FIFO transferDOC[S001-g-68s]DMA (68000 to SH-2 FIFO, SH-2 DMAC)
HENthe interrupt mask bit that allows H interrupts during vertical blank; one bit shared by both SH-2sDOC[S001-g-hen]System registers

Video#

termmeaningsee
VDPthe 32X video chip. It displays the frame buffer and lays it in front of or behind the Mega Drive's scroll planes and spritesDOC[S001-g-vdp]32X VDP overview
overwrite imagea second view of the frame buffer: a byte of 0 written through it leaves the old pixel in place, which suits drawing characters over a pictureDOC[S001-g-ow]Frame buffer and line table
auto fillthe VDP function that fills a run of frame buffer words with one value, started by a write to the fill data registerDOC[S001-g-fill]Auto fill (VDP frame buffer fill)
priority bit (through bit)the 16th bit of a colour; it puts that pixel on the other side of the Mega Drive pictureDOC[S001-g-prio]Palette (CRAM) and priority
H blank / V blankthe horizontal and vertical blanking periods: the part of each line, and of each frame, in which no picture is drawnV-blank and H-blank access rules
frame bufferthe 32X's video DRAM. It stores a line table and the picture data for each lineDOC[S001-g-fb]Frame buffer and line table
line tablethe per-line table that the frame buffer stores next to the picture dataDOC[S001-g-fb]Frame buffer and line table
direct colora mode where each pixel is stored as a color value of its ownDOC[S001-g-direct]Video modes (packed pixel, direct colour, run-length)
packed pixela mode where each pixel is a palette code, an index into the color paletteDOC[S001-g-packed]Video modes (packed pixel, direct colour, run-length)
run-length modea mode where the data is a palette code and a count of how many pixels in a row share itDOC[S001-g-run]Video modes (packed pixel, direct colour, run-length)
screen shifta control bit (SFT) that moves the picture by one dot, because in packed pixel mode the line table moves only in two-dot stepsDOC[S001-g-shift]Screen shift (1-pixel horizontal scroll)

Sound#

termmeaningsee
PWMpulse-width modulation: the 32X's sound output turns each sample into the width of a pulse, at 11-bit resolutionDOC[S001-g-pwm]PWM sound (registers, cycle, FIFO)
cycle registerthe PWM register that sets the length of one output period, counted in SH-2 clocks, and so the sample rateDOC[S001-g-cyc]PWM sound (registers, cycle, FIFO)
centre valuehalf the cycle width: the pulse width that means silence. Output that starts from 0 instead clicksSoftware mixing for PWM
