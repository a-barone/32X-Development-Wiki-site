Wiki/open-questions

Open questions

These are questions the sources leave open, grouped by the page they belong to. Where possible, each one says what would settle it, usually a test on a real console.

Cartridge bank switching#

  • Under which circumstances does an SH-2 hang when it accesses the cartridge while RV = 1? The 32XDK wiki's "Bank switching" page reports hangs, while the 32X Hardware Manual says the access waits.
    • What would settle it: a 32X test ROM in which each SH-2 reads the cartridge in a loop, through the cached and cache-through views, while the 68000 sets RV = 1 for varying times

DMA (68000 to SH-2 FIFO, SH-2 DMAC)#

  • How many bytes does one SH-2 DMA with TCR0 = $8000 and the 16-byte unit (CHCR0 = $5EE1) move on a 32X? Hitachi's SH7604 manual has TCR hold four times the transfer count for 16-byte units ($2000 transfers = 128 KB), while Mars Check's frame-buffer routines load TCR0 = $8000 at that unit and compare only $8000 words (64 KB).
    • What would settle it: an SH-2 test ROM with TCR0 = $8000 and CHCR0 = $5EE1 that copies a marked 128 KB source over a pre-filled destination and counts the changed bytes

Memory map#

  • What does the 68000 read at $000100-$3FFFFF with ADEN = 1 and RV = 0? The 32X Hardware Manual says cartridge ROM appears there only when RV = 1. Chilly Willy, in the GenDev forum thread "Limitations in current 32X emulators" (2012), calls $000000-$3FFFFF "32X BIOS space" with RV = 0 but does not say what the higher addresses return.
    • What would settle it: a 68000 test ROM on a 32X that reads $000100-$3FFFFF with RV = 0 and tells open bus, a mirror and a fixed value apart

System registers#

  • Do the SH-2 side's DREQ control bits 15 and 14 ($20004006) report the DREQ FIFO or the frame-buffer write FIFO? Sega's 32X Hardware Manual labels them "Frame Buffer, Write Cache Full/Empty", while the 68000-side FULL bit ($A15106 bit 7) is "DMA FIFO Full".
    • What would settle it: an SH-2 test ROM that reads $20004006 once with the DREQ FIFO filled from the 68000, and once with the frame-buffer write FIFO filled by SH-2 writes
  • When do the INTS and INTM bits ($A15102) return to 0: when the SH-2 takes the interrupt, when it writes the CMD clear register, or never without that write? Sega's 32X Hardware Manual says only that they are "automatically cleared if SH2 does not interrupt clear".
    • What would settle it: the 68000 polls $A15102 after setting INTM while the master SH-2 masks CMD, takes the interrupt without clearing it, or writes $2000401A
  • Does a write to a full PWM FIFO drop the oldest entry on a real 32X, as the 32X Hardware Manual says? Released code (Lusid Dreams, and Chilly Willy's code in the GenDev forum thread "simplest method for 32x sound?") waits while the FIFO is full, so it never writes to a full FIFO.
    • What would settle it: an SH-2 test ROM that fills the left FIFO with three distinct widths, writes a fourth while it is full, and records the next three samples at the PWM output
  • What do the pulse-width registers read back in bits 11-0 on a real 32X? The 32X Hardware Manual calls the value undefined, and released code reads only bits 15 and 14 (FULL and EMPTY).
    • What would settle it: an SH-2 test ROM that writes known widths, reads the register 100 times and logs bits 11-0
  • Does a write to HEN by the slave SH-2 change H interrupt delivery on the master? The 32X Hardware Manual says HEN is one bit shared by both SH-2s.
    • What would settle it: an SH-2 test ROM in which the slave toggles HEN while the master counts H interrupts per frame

Auto fill (VDP frame buffer fill)#

  • Does an auto fill run at the documented rate (7 + 3 x length Scyc) during active display as well as in blanking? Scyc is 1/23.01 MHz on NTSC and 1/22.8 MHz on PAL, per Sega's "32X Introduction and System Features" (April 1994), page 50.
    • What would settle it: an SH-2 test ROM that times fills of known length (FEN going from 1 to 0) with the FRT, in blanking and in active display

Frame buffer and line table#

  • Are cached SH-2 reads of the frame buffer ($04000000) usable, and under what purge rule? The 32X Hardware Manual's SH-2 map lists the cached address, but its VDP chapter allows only cache-through access except for the palette. On the jgenesis emulator cached frame-buffer reads stay stale until the line is purged, as with SDRAM.
    • What would settle it: an SH-2 test ROM that writes a pattern through $24000000 and reads it through $04000000 with and without a cache purge
  • Is the frame-buffer mirror at $24040000-$24060000 present on retail 32X units? The 32XDK wiki's "Video" page reports it from the Soulstar X prototype, and the helios32x and ares emulators added it so that the prototype shows its 32X layer (ares issue #744). The 32X Hardware Manual shows nothing there.
    • What would settle it: an SH-2 test ROM that writes $24000000 and reads $24040000, run on retail units of each revision
  • What does a real 32X show on a line whose line-table entry leaves fewer than 320 pixels of DRAM before the end of the frame buffer? The 32X Hardware Manual's layout suggests overwrite-image data; the jgenesis emulator wraps to DRAM word 0.
    • What would settle it: an SH-2 test ROM on a real 32X with a line-table entry near $FFFF, photographing that line
  • How fast does an SH-2 DMA channel write the frame buffer on a real 32X, compared with a CPU copy? Sega's Mars Check program does it (auto-request, 16-byte unit, word compare afterwards); d32xr does not. On the jgenesis emulator all words arrive and the DMA is faster.
    • What would settle it: an SH-2 test ROM on a real 32X that DMAs a pattern from SDRAM to $24000000, reads it back, and times it against a CPU copy with the FRT or WDT

Mixing the 32X picture with the Mega Drive VDP#

  • What does a real PAL 32X show when the bitmap mode register selects 240 lines while the Mega Drive VDP stays in 224-line mode? The 32X Hardware Manual allows 240 lines only with the Mega Drive in 40 x 30 cells. The jgenesis emulator keeps a 320 x 224 frame, and 32X lines 224-239 stay hidden.
    • What would settle it: a PAL 32X test ROM that photographs lines 224-239 with the Mega Drive VDP in V28, then in V30

Video modes (packed pixel, direct colour, run-length)#

  • In run-length mode, which byte of a pixel word holds the count, and does a count of n draw n or n + 1 pixels? Community posts (the Sega-16 forum thread "32X graphics modes" and examples in the GenDev forum thread "Frame Buffer Switch") put the count in the first byte and draw n + 1 pixels. For packed pixels, Lusid Dreams writes pixel x at byte offset x, so the high byte is the left pixel.
    • What would settle it: a test ROM that draws known run-length words and checks the screen

PWM sound (registers, cycle, FIFO)#

  • What does Sega's "11-bit" PWM resolution refer to, when the cycle and pulse-width fields are 12 bits wide (0-4095)? Community posts in the GenDev forum say usable values run from 1 to the cycle value minus 1, so the bits per sample depend on the rate; Sega's April 1994 "32X Introduction and System Features" gives 10 bits at 22 kHz.
    • What would settle it: a recording of the PWM output on a retail unit while the pulse width sweeps at a fixed cycle value
  • Can the documented interrupt-order hazard be seen on a real 32X, and how close must the two interrupts be? The 32X Hardware Manual warns that a higher-level interrupt following a lower one may be taken first, such as an H interrupt just before a V or PWM interrupt.
    • What would settle it: an SH-2 test ROM on a real 32X that arms the H interrupt a few lines before the V and PWM interrupts and logs the order taken over many frames
  • On a production 32X, how loud is PWM against FM at full scale, and is the PWM carrier audible at low rates? Sega's Technical Bulletin #20 "Modification to improve PWM sound" describes a fix, and TMorita, in the GenDev forum thread "Super VDP", remembers a low-pass filter.
    • What would settle it: a recording of full-scale PWM and FM tones and a low-rate PWM tone from a real 32X's audio output, comparing levels and spectra

Dual-CPU synchronisation on the 32X#

  • Does the communication-port rule (a simultaneous write, or a write during a read, leaves the value undefined) also hold between the master and slave SH-2? The 32X Hardware Manual states it for the 68000 against an SH-2.
    • What would settle it: a test ROM in which the master and slave write one port in a tight loop while the other reads it, counting torn values
  • How many clocks does handing the bus from one SH-2 to the other cost? The 32XDK wiki's Optimizations page gives 2 to 3 clocks. ob1, in the GenDev forum thread "Concurrency penalty" (2021), measured the 6 to 10% slow-down of running both SH-2s on a real PAL 32X, but not the hand-off itself.
    • What would settle it: a test ROM that times one SH-2 loop with the other SH-2 idle, then with it hammering SDRAM
  • Can one SH-2 interrupt the other by any path other than the SCI receive interrupt? The 32X Hardware Manual's CMD interrupts come from the 68000 only. TascoDLX, in the GenDev forum thread "Mars Check Program results for Kega Fusion v3.61", reports that the X-Men prototype has the master raise a slave interrupt through the SCI.
    • What would settle it: a test ROM that tries each interrupt source from the other SH-2

The SH-2 on the 32X#

  • Is the SH7604 manual exact for the SH7095, the part number the 32X Hardware Manual gives for the 32X's SH-2? The 32XDK ships Hitachi's SH7604 manual; cache, CCR and bus arbitration are where a difference would matter.
    • What would settle it: a test ROM that exercises the CCR two-way mode and the associative purge on hardware
  • Why does Sega forbid TAS on the 32X, and what does TAS do there, on SDRAM, on cache-through addresses and from both SH-2s? The 32X Hardware Manual gives the rule without a reason.
    • What would settle it: a test ROM that runs TAS on SDRAM from both SH-2s and checks the result
  • What does CCR read at application entry on a real 32X? The 32X manual (R4, page 66) says the boot ROM purges and enables both caches before the application starts, and the boot ROM writes $11 to each CPU's CCR, so $01 is expected once CP clears itself.
    • What would settle it: a read of CCR at $FFFFFE92 at application entry on hardware
  • Which bus states give which cost for an SH-2 cartridge ROM read? bakemono's figure of 8 cycles per word (quoted on the 32XDK wiki's "SH2 on the 32X" page) sits inside the manual's 6 to 15 waits.
    • What would settle it: a test ROM that times SH-2 ROM reads with the 68000 idle, then reading the cartridge, then holding RV = 1

Keep the 68000 off the cartridge#

  • How much SH-2 time does 68000 code running from cartridge ROM cost, and does it slow an SH-2 that never touches the cartridge? The 32X Hardware Manual puts the cartridge on the same bus as the 32X hardware.
    • What would settle it: a test ROM that times an SH-2 loop reading cartridge ROM, then one working only in SDRAM, each with the 68000 looping in ROM and then in work RAM

SH-2 DMA in 16-byte mode#

  • How much faster are 16-byte DMA units than longword units for an SDRAM-to-SDRAM copy on the 32X, in the cycle-steal mode Sega requires?
    • What would settle it: a test ROM that times the same SDRAM copy with TS = 10 and TS = 11 using the FRT

Work during the frame-buffer swap#

  • How much frame time does moving game logic between the FS write and the swap wait recover in a real 32X game loop?
    • What would settle it: a test ROM with a fixed logic load that times frames with the busy-wait right after the FS write, against the reordered loop

Wide frame-buffer writes#

  • Does an SH-2 byte write to the frame buffer cost the same clocks and FIFO space as a word write, and does a longword write take one FIFO entry or two? Snake, in the GenDev forum thread "Super VDP" (2009), says from experience that sustained writes cap at one per 5 cycles and that longwords are no faster but stall 10 cycles.
    • What would settle it: a test ROM that times byte, word and longword frame-buffer writes with the FIFO empty and full, using the FRT

Profile with the SH-2 free-running timer#

  • Does a word write to FTCSR ($FFFFFE11), a byte register at an odd address, raise an address error on the 32X's SH-2? d32xr's FRT overflow handler of 2021 cleared FTCSR that way, and Hitachi says word accesses to odd addresses raise an address error; today's d32xr has no FRT overflow handler.
    • What would settle it: a test ROM on hardware that lets the FRT overflow with that handler installed

Longword alignment and pipeline spacing#

  • What does longword-aligning MA-stage instructions, and spacing multiply and load-use pairs, gain on 32X code running from the cache? ob1, in the GenDev forum thread "Contention Between Instruction Fetch and Memory Access" (2021), measured 4 to 8% from fetch and memory contention on one loop on a real PAL 32X.
    • What would settle it: a test ROM that times one cached loop in two layouts (MA at a longword and at a word boundary) with the FRT

Batch small writes in the SH-2 on-chip RAM#

  • When one SH-2 writes a block of words to SDRAM, does it keep the bus across the words, or re-arbitrate with the other SH-2 for each access? Sega's R4 manual says the slave requests the bus for each external access; the answer decides whether batching writes saves bus hand-offs.
    • What would settle it: a test ROM that times a block copy by the slave while the master also uses SDRAM, against the same writes scattered

Debugging (GDB remote stubs for the SH-2)#

  • How does a GDB stub running on a retail 32X SH-2 talk to the host? The SH-2 serial port links master and slave and NMI is tied high (32X Hardware Manual), and both SH stubs (sh-stub.c and Bill Gatliff's gdbstubs) use a board serial port.
    • What would settle it: a stub that relays GDB packets through the communication ports to a 68000-side link, run on a retail 32X with GDB attached
  • Does the SH7604's user break controller step correctly across delay slots and branches? Bill Gatliff, in his article on writing a GDB agent, reports that some SH versions have a defective UBC there, without naming them.
    • What would settle it: an SH-2 test ROM on a 32X that sets a UBC break on the fetch of a delay-slot instruction after BRA, BT/S and JMP, and logs where the break lands
  • Do jgenesis, PicoDrive or Kega Fusion offer a GDB server for the 32X's SH-2s? GensKMod and BlastEm serve the 68000 only, and the GDB servers of ares and MAME cannot serve the SH-2s (see the Debugging page).
    • What would settle it: an emulator's documentation or source that describes SH-2 GDB support

Devkits (Chilly Willy's devkit, marsdev)#

  • Did a later release of Chilly Willy's devkit ship gdb? In January 2023 he planned to add gdb "for folks that use gens-kmod"; the notes of release 20220418 name gcc, binutils, newlib and zasm.
    • What would settle it: the contents of a later release of the devkit

32X development and documentation timeline#

  • When did the 32X go on sale in France and Spain, and when did Sega stop making it? October 1994 magazines give only planned dates (Player One: start of December; Hobby Consolas: end of November). AllGame puts the end of production in early 1996, but no Sega statement dates it.
    • What would settle it: a dated source, such as a Sega press release or annual report or a magazine quoting Sega
