PWM sound (registers, cycle, FIFO)

The 32X produces its own sound with a PWM (pulse-width modulation) unit: the program writes a number per sample, and the hardware turns that number into a pulse whose width sets the output level. This page describes its registers, how the sample period is chosen, how the small FIFO (first-in, first-out queue) behaves and which traps to avoid. Read it before you write any code that plays samples through the 32X.

Summary#

  • What it is. A 2-channel pulse-wave sound source. The integrated pulse turns pulse width into wave heightDOC[S001-3-2ch]. Sega rates it as D/A conversion with 11-bit resolutionDOC[S001-3-11bit].
  • Registers. Five registers, reachable from both the SH-2 and the Mega DriveDOC[S005-3-five]. They sit at $A15130 to $A15138 on the 68000 side and $20004030 to $20004038 on the SH-2 side (table below).
  • Sample period. One cycle register sets it for both channels. It is counted in a fixed base clock of 23.01 MHz (NTSC) or 22.8 MHz (PAL)DOC[S005-3-base].
  • FIFO. Each channel's pulse width register is a 3-step FIFODOC[S005-3-fifo3][S005-3-fifo3b] with FULL and EMPTY flagsDOC[S001-3-full][S001-3-empty].
  • Interrupt and DMA. The PWM can raise an SH-2 timer interrupt every TM samples, and can drive DMA channel 1 through DREQ1DOC[S005-3-funcs].

PWM control register ($A15130 / $20004030)#

The control register chooses which channel goes to which output, how often the timer interrupt fires and whether the FIFO requests DMA. Bits 15 to 12 and 6 to 4 are unused.

Bit15-1211-876-43210
Field-TM3-TM0RTP-RMD0RMD1LMD0LMD1

The layout is the one the 32X Hardware Manual gives for the PWM control registerDOC[S005-3-ctlbits]DOC[S001-3-ctlbits].

Note the bit order of the two mode fields. RMD0 is bit 3 and RMD1 is bit 2, so RMD0 is the high bit of the right-mode pair. In the same way LMD0 is bit 1 and LMD1 is bit 0. The tables below read each pair in that order, high bit first.

  • Example. Chilly Willy's player, posted with its source in the Sonic Retro forum thread "Interrupt-Driven DMA PWM on the 32X" (2012), writes 0x0185 and comments it as TM 1, RTP on, RMD = right, LMD = leftCODE[S046-3-ctl].
  • Decoding 0x0185. Bits 11-8 hold 1 (TM = 1) and bit 7 is set (RTP on). Bits 3-0 are 0101: RMD0 RMD1 = 01 (right) and LMD0 LMD1 = 01 (left), which matches the comment under the R4 tablesDERIVED[S046-3-ctl].
  • Bit 4 in the Genesis 32X US Overview. This Sega document, part of the same 32XDK documentation release as the R4 manual, prints bit 4 as MONO: 0 = stereo (initial value), 1 = monoDOC[S005-3-ovmono]. It adds that in mono mode only the registers used for mono are validDOC[S005-3-ovmonovalid].
    • The R4 manual leaves bit 4 unused.
    • 0x0185 leaves bit 4 at 0, the stereo setting in the Overview, so released code never sets itDERIVED[S046-3-ctl].
  • The left-mode table is printed two ways. The R4 manual gives LMD 01 = left and 10 = rightDOC[S005-3-lmd].
    • The Genesis 32X US Overview prints the left-mode table with 01 = R and 10 = LDOC[S005-3-ovlmd].
    • Chilly Willy's register list, posted in the GenDev forum thread "32X Audio" (2008), follows the OverviewCOMM[S049-3-lmd].
    • His own player code writes 01 and comments it as left, which follows the R4 manualCODE[S046-3-ctl].
    • If left and right come out swapped on a console, swap the values of the two mode fields.

Cycle register ($A15132 / $20004032)#

The cycle register sets how long one sample lasts. A smaller value gives a higher sample rate but a smaller range of sample values, because a sample cannot be larger than the cycle.

  • Size. Cycle and pulse width are both 12-bit values, 0 to 4095DOC[S005-3-12bit].
  • Base clock. It is 23.01 MHz on NTSC and 22.8 MHz on PAL. The register page says the register value times that clock period (Scyc) is the cycleDOC[S001-3-scyc].
  • Special values. Value 0 gives the longest period, 4095 base clock periodsDOC[S005-3-zero]. Value 1 stops the PWM and must not be setDOC[S005-3-one].
  • Clock values. The Sega Retro wiki's 32X technical specifications page gives the clocks as 23.01136 MHz (NTSC) and 22.801467 MHz (PAL)COMM[S013-3-clk].

The formula to use: cycle = round(clock / rate) + 1.

  • Chilly Willy's player in the Sonic Retro thread programs exactly this, with clocks of 23011361 Hz (NTSC) and 22801467 Hz (PAL)CODE[S046-3-cycn].
  • d32xr, the GitHub source of Doom 32X Resurrection, uses the same formula and the same 0x0185 control value in its PWM set-upCODE[S097-3-init].
  • The + 1 follows the manual's chapter 1.7, which counts the sample period as (value - 1) base clock periodsDOC[S005-3-minus1].
  • The manual's own example divides 23.01 MHz by (1047 - 1) to get a 22 kHz sampling rateDOC[S005-3-1047].
  • Worked example for 22050 Hz. On NTSC, 23011361 / 22050 = 1043.6, which rounds to 1044, plus 1 gives 1045. On PAL, 22801467 / 22050 = 1034.1, which rounds to 1034, plus 1 gives 1035DERIVED[S046-3-cycder].
  • What the + 1 is worth. It changes the period by one base clock in about 1045, about 0.1 % in pitchDERIVED[S046-3-cycder]. The register pages and chapter 1.7 disagree on it (see "Where sources disagree" below).
  • A common value. Chilly Willy calls a cycle of 1048 (about 22 kHz) very popular in 32X games. MEGADRIVE Jeroi, who opened the Sega-16 forum thread "32x sound programming" (2013), reposts that explanation thereCOMM[S051-3-22k].

The sample range to use. The cycle sets the rate and the largest sample value at once, so the range shrinks as the rate goes up.

  • Chilly Willy explains in the GenDev forum thread "DMA to PWM" (2009) that the cycle count sets both the sample rate and the largest sample valueCOMM[S048-3-max].
  • Graz, who opened that thread to get DMA-driven PWM working, sums it up: a higher sample rate means a lower bit depthCOMM[S048-3-trade].
  • In the release post of his mod player (GenDev forum, 2011), Chilly Willy says 22 kHz allows a 10-bit sampleCOMM[S047-3-10bit].
  • mic, the author of the Lusid Dreams SID music player for the 32X, gives figures in the Sega-16 forum thread "32x mod player" (2019): 22050 Hz on a PAL unit gives a maximum sample value of 1034 (22800000 / 22050)COMM[S069-3-1034].
  • Use 2 as the minimum and a maximum below the cycle value. d32xr uses 2 to 1032 at 22050 HzCODE[S097-3-1032].
  • 1032 sits below both the NTSC cycle of 1045 and the PAL cycle of 1035, so the one range works on both kinds of consoleDERIVED[S046-3-cycder].
  • Chilly Willy's mixer example in "32X Audio" uses the same range for 22050 Hz: minimum 2, centre 517, maximum 1032CODE[S049-3-defs]. To convert signed PCM, scale it to +/-(centre - minimum), then add the centreCODE[S049-3-conv].

Pulse width registers#

The pulse width registers are at $A15134, $A15136 and $A15138 on the 68000 side and $20004034 to $20004038 on the SH-2 side. Each holds a 12-bit sample and two status flags.

Bit151413-1211-0
FieldFULLEMPTY-pulse width
Accessread onlyread only-write only

The layout is given by the manualDOC[S001-3-pwbits].

  • FULL = 1 means there is no space left in the FIFO; 0 means space is availableDOC[S001-3-full].
  • EMPTY = 1 means no data is in the FIFODOC[S001-3-empty].
  • Read-back. Bits 11 to 0 read back as undefined dataDOC[S001-3-wo].
  • Mono register. A write to it writes the same value to left and rightDOC[S001-3-mono]. Chilly Willy adds in "32x sound programming" that it is not a third channelCOMM[S051-3-mono].
  • Height. Written values are sample heights measured from the most negative point. Chapter 1.7 says the height is value - 1, so 1 is the most negative (0) and 0 the most positive (4095)DOC[S005-3-height].
    • The register page of the manual gives the pulse width as value x Scyc, without the - 1DOC[S001-3-pwscyc].
    • Chilly Willy's register list in "32X Audio" agrees with the - 1: amplitude is width - 1, 0 = full (4095)COMM[S049-3-amp].
  • Practice. A 32-bit write to $20004034 sets left and right together (used as the DMA destination)CODE[S046-3-long]. FULL can be polled through the mono register, bit 15CODE[S046-3-full].

FIFO behaviour#

  • Each of left and right has its own 3-step FIFODOC[S001-3-3step].
  • The output pulse width is updated once per sampling cycle. With the FIFO empty, the last width is heldDOC[S005-3-hold].
  • After reset the FIFO is empty and the pulse width is 0DOC[S005-3-reset].
  • Writing while FULL discards the oldest entry, shifting the FIFO by oneDOC[S001-3-oldest].
  • With both outputs off the cycle counter is stopped, so FULL stays 1 until a channel is turned onDOC[S001-3-stuck].
  • With only one output on, the other channel's FIFO still drains: its data disappears and nothing is heardDOC[S001-3-offside].
  • The cycle counter stops when both left and right outputs are offDOC[S001-3-stop].

Interrupt#

  • The PWM timer interrupt is SH-2 level 6, the lowest of the five 32X interruptsDOC[S001-3-lvl].
  • It is masked by the PWM bit (bit 0) of the SH-2 interrupt mask register $20004000; 1 enables itDOC[S005-3-mask]. The V, H, CMD and PWM mask bits are separate for master and slaveDOC[S001-3-perside].
  • It is cleared by writing the PWM interrupt clear register ($2000401C, word, SH-2 side). That register's description says that if it is not cleared, the interrupt will no longer occurDOC[S001-3-clr].
  • The interrupt-sources section says instead that an interrupt keeps occurring until it is clearedDOC[S001-3-until]. Clearing it in every handler is right under both readings.
  • The manual's register table describes the clear register's use as "sampling data write timing"DOC[S001-3-clruse].
  • In "32x sound programming", Chilly Willy says Sega's sample code fed the PWM from interrupts because of DMA sound bugs on the first developer unitsCOMM[S051-3-devbug]. He adds that consumer 32Xs do not have those bugsCOMM[S051-3-retail].

Example: set up the PWM and write one stereo sample#

The routine below is d32xr's PWM set-up (Mars_InitPWM in marshw.c) without its start-up ramp, plus a polled write of one stereo sample; the register macros are d32xr's 32x.h namesCODE[S097-3-init].

/* d32xr's sample range for 22050 Hz (marssound.c) */
#define SAMPLE_MIN  2
#define SAMPLE_MAX  1032

void pwm_init(int rate)
{
    /* three writes to the mono register prime both FIFOs */
    MARS_PWM_MONO = 1;
    MARS_PWM_MONO = 1;
    MARS_PWM_MONO = 1;

    /* cycle = round(clock / rate) + 1, in integer arithmetic */
    if (MARS_VDP_DISPMODE & MARS_NTSC_FORMAT)
        MARS_PWM_CYCLE = (((23011361 << 1) / rate + 1) >> 1) + 1;
    else
        MARS_PWM_CYCLE = (((22801467 << 1) / rate + 1) >> 1) + 1;

    /* TM = 1, RTP on, right mode = right, left mode = left */
    MARS_PWM_CTRL = 0x0185;
}

/* l and r must already lie in SAMPLE_MIN..SAMPLE_MAX */
void pwm_write(unsigned short l, unsigned short r)
{
    while (MARS_PWM_MONO & 0x8000)  /* bit 15 is FULL: wait */
        ;
    MARS_PWM_LEFT = l;              /* word write, left FIFO */
    MARS_PWM_RIGHT = r;             /* word write, right FIFO */
}

The cycle line doubles the clock, divides, adds 1 and halves again, which rounds the division to the nearest whole number. At 22050 Hz it programs 1045 on NTSC and 1035 on PAL (worked example above). pwm_write polls FULL through the mono register the way Chilly Willy's player does, then writes each channel as a word, the only SH-2 access Bulletin 19 allows. A real player ramps the output to the centre value first (see Pitfalls) and feeds the FIFO by DMA instead of polling (DMA-driven PWM).

Techniques#

  • Three ways to feed the FIFO. From the PWM interrupt (TM samples per interrupt), by polling FULL, or by DMA on DREQ1 (RTP = 1).
  • DMA-driven PWM is on DMA-driven PWM.
  • Mixing. At a cycle of 1048 (about 22 kHz), Chilly Willy notes that four signed 8-bit voices add up to -512 to 508, which fits around the centre valueCOMM[S051-3-four]. Software mixing for PWM works through the budget.
  • At 11 kHz, the rate Chilly Willy says games like Doom use, eight 8-bit streams can be summed without saturating. He writes this in the GenDev forum thread "Super VDP" (2008)COMM[S036-3-11k].
  • A caution. TMorita, a GenDev forum member who signs his posts Toshi, describes his work on the Doom 32X sound driver in the thread "Super VDP". He found that summing 8 channels left each one very faint, and settled on about fourCOMM[S036-3-faint].

Pitfalls#

A click at start-up. The PWM output starts at 0COMM[S049-3-start0], while silence is the centre valueCOMM[S049-3-centre]. Ramp the output from the minimum up to the centre before you play.

  • Chilly Willy's player in the Sonic Retro thread does this ramp, to avoid a click on a real 32XCODE[S046-3-ramp].
  • The release notes of Chilly Willy's mod player then report no click at start-up on real hardwareCODE[S047-3-click].
  • d32xr carries the same rampCODE[S097-3-ramp].

Code that plays in an emulator can fail on a console. Test PWM code on hardware.

  • Chilly Willy released his mod player in the GenDev thread "MOD Player for 32X - the Good Enough release" (2011). There he writes that DMA-driven PWM did not play properly on stock Gens/GS r7 or on the Kega Fusion emulator of that timeEMU[S047-3-emu].
  • Graz reports in "DMA to PWM" that the GensKMod emulator he was testing on did not support DMAEMU[S048-3-gkm].
  • In the Sonic Retro thread, Chilly Willy says Fusion 3.63 sounds bad with interrupt-driven DMA PWM, while 3.64 worksEMU[S046-3-emu].
  • Chilly Willy also reports the same player working on real hardwareHW[S046-3-hw].

Auto-request DMA can starve the PWM. When either SH-2 drives the PWM, auto-request DMA must not be used, because PWM data writes may not happen in timeDOC[S001-3-nodma]. Use external request (DREQ1) for the PWM channel.

  • DMA from memory to the PWM FIFO through DREQ1 is a separate, documented set-up (see DMA-driven PWM).
  • d32xr, which plays PWM by DMA, sets its PWM DMA channel to external request (DREQ1), not auto-requestCODE[S097-3-extreq].

Interrupts can arrive out of order. A higher-level interrupt that follows a lower one may be taken first. The manual warns about an H interrupt just before a V or PWM interruptDOC[S001-3-order]. Do not rely on the PWM interrupt landing after an H interrupt that came first.

A PWM interrupt that is not cleared misbehaves. The manual gives two outcomes: one passage says it keeps occurring until clearedDOC[S001-3-until], another says it will no longer occurDOC[S001-3-clr]. Either way, clear it in every handler.

  • Lusid Dreams, mic's SID player (source on GitHub), does this: its PWM handler writes the clear register first, then pads with NOPs before returningCODE[S087-3-clr].

A sample value of 1 may sound wrong. The manual makes 1 the most negative pointDOC[S005-3-height]. mic says the minimum allowed value is 2COMM[S069-3-min2]. He adds that values outside the valid range sound wrong on a real 32XCOMM[S069-3-range]. Use 2 as the minimum.

  • d32xr uses 2CODE[S097-3-min2].

SH-2 byte writes to a pulse width register can add samples. Use word writes from the SH-2, as Bulletin 19 requiresDOC[S081-3-word].

  • On the jgenesis emulator each SH-2 byte write adds its own FIFO entry, so an upper and lower byte pair makes two samples; see the emulator section below.
  • d32xr declares the pulse width registers as 16-bit and writes them as words, or as longs by DMACODE[S097-3-word].

PWM and FM at full level distort. On target Ver. 2.0x development boards the PWM was much quieter than FM, and Sega changed two resistors. Production units already carry the changeDOC[S082-3-vol].

  • Sega's Technical Bulletin 20 ("Modification to improve PWM sound", September 1994) says that by maximizing both sound sources the sound after mixing becomes distortedDOC[S082-3-dist].
  • It adds that, because of a wider dynamic range, the PWM sound at peak time tends to get distorted when set through an average sound volumeDOC[S082-3-dist].
  • The bulletin's advice is to set both volumes after mixing so that the sound is not distortedDOC[S082-3-set]. In practice, leave headroom in the PWM mix rather than driving it to the full range.

Low sample rates give a carrier whine. TMorita writes in "Super VDP" that a sampling rate that is too low gives a high-pitched carrier whineCOMM[S036-3-whine]. Keep the rate up.

  • TMorita recalls an audio filter in the production 32X that reduces it, and a problem with it on the development boardsCOMM[S036-3-whine].
  • For the Doom 32X sound driver, TMorita ran the DAC at twice the sampling rate and fed each value in twice to remove itCOMM[S036-3-2x].

Sega's 11-bit figure does not give the range at your rate. Sega quotes 11-bit resolutionDOC[S001-3-11bit] while the fields are 12 bits wideDOC[S005-3-12bit]. Work out the range from the cycle value instead.

  • The "GSX Hardware Specifications" table in Sega's "32X Introduction and System Features" (April 1994) gives "10 bits at 22 kHz" insteadDOC[S006-3-10bit]. That fits the rate-dependent range described under the cycle register.
  • d32xr's 22050 Hz range tops out at 1032CODE[S097-3-1032], about 10 bits of range (1032 - 2 = 1030 steps; 2^10 = 1024)DERIVED[S097-3-1032].

Tested on the jgenesis emulator#

These results come from jgenesis 0.14.1, jsgroth's emulator whose source is on GitHub, run with a small 32X test ROM. Nobody has confirmed them on a real 32X yet.

  • With both FIFOs drained, the right FIFO reads FULL after 3 word writes.
  • On the left channel, an SH-2 byte pair plus one word fills the FIFO, so each byte write added an entryEMU:jgenesis core 0.14.1[T209-byte].

Where sources disagree#

  • Cycle and pulse width: value x Scyc, or value - 1? The manual's register pages (R4 manual page 26, and the same pages in the 32XDK copy) say value x Scyc. The PWM part of chapter 1.7 (R4 manual page 59) says value - 1.
    • Chilly Willy's register list in "32X Audio" says the sample period is the SH clock / (cycle - 1), with 0 meaning the full count (4095)COMM[S049-3-period]. He repeats it in "DMA to PWM": rate = 23.01 MHz / (count - 1) on NTSCCOMM[S048-3-rate].
    • Graz computes the cycle in the same thread as clock / rate, with no - 1COMM[S048-3-noover].
    • The manual's worked example cannot settle it: 23.01 MHz / 1046 = 22.00 kHz and 23.01 MHz / 1047 = 21.98 kHz both round to 22 kHzDERIVED[S005-3-1047].
    • Released code uses the - 1 reading (the formula above)CODE[S097-3-plus1].
  • SH-2 byte writes to the pulse width registers. The manual allows them; Bulletin 19 of 23 September 1994 forbids them, and as the later official text it is the rule to follow.
  • Minimum sample value. The manual makes 1 the most negative point, and Chilly Willy agrees in "DMA to PWM"COMM[S048-3-min1]. mic says "(AFAIK) always 2" in "32x mod player"COMM[S069-3-min2].
  • Left-mode bits. The R4 manual and Chilly Willy's player code make LMD 01 the left channel. The Genesis 32X US Overview and Chilly Willy's "32X Audio" register list make it the right channel.
  • An uncleared PWM interrupt. Section 3.2.2 says in one place that it keeps occurring and in another that it no longer occurs.
