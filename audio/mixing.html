Software mixing for PWM

This page explains how a 32X program combines several sound voices into the two PWM output channels. It covers the sample-value budget at a given rate, the conversion from signed PCM to unsigned pulse widths, a commented mixer from released code, and the errors that show up as faint, distorted or clicking sound. Read PWM sound (registers, cycle, FIFO) first for the registers; come here when you write the mixer.

Summary#

  • Mix in software. The PWM chip has two output channels and no mixer of its own. Several voices must be added into one sample per channel per sample period (hardware side on PWM sound (registers, cycle, FIFO)).
  • The basic recipe. Add the signed PCM voices, scale the sum to fit the pulse-width range, then add the centre value to make it unsigned. Chilly Willy gives this recipe in the GenDev forum thread "DMA to PWM" (2009)COMM[S048-15-recipe].
  • Mix wide, scale late. Chilly Willy's player for MOD music files mixes in 16 bits. It scales to the PWM's 10-bit range only when it fills the DMA output buffer. He released it in the GenDev thread "MOD Player for 32X - the Good Enough release" (2011)CODE[S047-15-16].
  • Centre on the middle of your range. Use (minimum + maximum) / 2 as the silence value, and clamp every mixed sample to the range before it reaches the PWM (details below).

Details#

The sample budget#

The cycle width is the number of PWM clocks per sample. The PWM can output values from the minimum up to just below that width, so the width caps how loud the sum of all voices can get.

  • Chilly Willy's worked example in "DMA to PWM". At 22050 Hz the cycle count is 1044. Four signed 8-bit voices sum to -512..+511, and adding 520 puts them at 8 to 1031, inside the rangeCOMM[S048-15-520].
  • The same budget at a cycle width of 1048. Four 8-bit voices give -512 to 508 around a centre of 524, so they fit in the cycle width at 22 kHzCOMM[S051-15-four]COMM[S051-15-fit]. Chilly Willy wrote this explanation, and MEGADRIVE Jeroi, who opened the Sega-16 forum thread "32x sound programming" (2013), reposts it there.
  • The rule behind both. The centre value is half the cycle width, and samples must be limited to plus or minus half of (cycle width - 2)COMM[S051-15-centre].
  • At 11 kHz, eight 8-bit streams can be summed without saturating, Chilly Willy writes in the GenDev forum thread "Super VDP" (2008)COMM[S036-15-11k].

Which centre value to use#

Four centre values appear in the sources: 520, 524, 517 and 515. They are one rule, "silence sits in the middle of the usable range", applied to different ranges.

  • 520 and 524 are about half of the cycle value: 1044 in "DMA to PWM" and 1048 in the Sega-16 repost (see the budget above).
  • 517 is the centre in Chilly Willy's mixer example, posted in the GenDev forum thread "32X Audio" (2008), for a range of 2 to 1032CODE[S049-15-defs].
  • 515 is d32xr's centre for the same 2 to 1032 range, written as (maximum - minimum) / 2CODE[S097-15-range].
  • d32xr's formula gives (1032 - 2) / 2 = 515, two steps below the midpoint (2 + 1032) / 2 = 517DERIVED[S097-15-range].

For a new mixer, take the range first (see PWM sound (registers, cycle, FIFO) for the minimum of 2 and the maximum below the cycle value) and use (minimum + maximum) / 2 as the centre. A centre a few steps off the midpoint, like d32xr's 515, only moves silence by those steps and takes the same number of steps of headroom from one side; the clamp keeps the output legal either way.

A mixer step by step: d32xr#

d32xr is the GitHub source of Doom 32X Resurrection, a homebrew rework of Doom for the 32X. The code below is abridged from S_Update in its sound file marssound.c; it mixes every active voice into a signed 16-bit stereo buffer and then turns that buffer into PWM samples in placeCODE[S097-15-conv].

#define SAMPLE_MIN     2
#define SAMPLE_MAX     1032
#define SAMPLE_CENTER  (SAMPLE_MAX-SAMPLE_MIN)/2   /* = 515 */

/* 1. Clear the buffer: one 32-bit word holds a left and a right
      signed 16-bit sample */
b2 = (int32_t *)buffer;
for (i = 0; i < MAX_SAMPLES; i++)
    *b2++ = 0;

/* 2. Mix: each active voice is scaled and added into the buffer */
for (i = 0; i < SFXCHANNELS; i++) {
    sfxchannel_t *ch = &sfxchannels[i];
    if (!ch->data)
        continue;                   /* voice not playing */
    painted += S_PaintChannel(ch, buffer, painted);
}

/* 3. Convert: add the centre, clamp, pack the two halves back */
c = SAMPLE_CENTER, l = SAMPLE_MIN, h = SAMPLE_MAX;
b2 = (int32_t *)buffer;
for (i = 0; i < MAX_SAMPLES; i++) {
    int s, s1, s2;
    s = (int16_t)(*b2 >> 16) + c;        /* upper half: left */
    s1 = (s < l) ? l : (s > h) ? h : s;  /* clamp to SAMPLE_MIN..MAX */
    s = (int16_t)(*b2) + c;              /* lower half: right */
    s2 = (s < l) ? l : (s > h) ? h : s;
    *b2++ = (s1 << 16) | s2;             /* both halves, same word */
}

The buffer stays signed while voices are added, so a loud voice and a quiet one can be summed without any offset getting in the way. Only the final pass adds the centre and clamps, once per output sampleCODE[S097-15-clamp]. Each 32-bit word is split, converted half by half and packed back into the same halvesCODE[S097-15-pack]CODE[S097-15-b2]. The upper half is the left channel: d32xr's assembly voice mixer, S_PaintChannel8 in sh2_mixer.s, shifts the scaled left sample into the upper 16 bits before adding itCODE[S203-15-left]. The packed buffer is what the DMA then copies to the left pulse width register, one long per stereo pair (DMA-driven PWM).

Pitfalls#

More voices, quieter voices. Summing many voices with no scaling leaves each one faint. Scale each voice as you add it.

  • TMorita, a GenDev forum member who signs his posts Toshi, describes his work on the Doom 32X sound driver in the GenDev forum thread "Super VDP" (2008). There he found that plainly summing 8 channels left each channel very faint, and kept to about fourCOMM[S036-15-faint].
  • In the same "Super VDP" post TMorita suggested converting each channel to a logarithmic value before mixingCOMM[S036-15-log].
  • d32xr's voices carry a scale factor when they are painted into the bufferCODE[S097-15-scale]. Its final clamp is a safety net, not a replacement for scaling.

A sum outside the pulse-width range sounds wrong on hardware. Clamp the final sum to the range's minimum and maximum, as step 3 of the code above does.

  • bakemono opened the Sega-16 forum thread "32x mod player" (2019) with a MOD player of his own. He then reported that it made no sound on his new 32X because it wrote values that were too largeHW[S069-15-toolarge].
  • mic wrote the Lusid Dreams SID music player for the 32X. He replied that anything outside the valid range sounds "all kinds of messed up" on real hardware, if it makes any sound at allCOMM[S069-15-range].

A click at start-up. Silence is the centre value, not 0, and the output starts at 0. Ramp the output from the minimum to the centre before you play.

  • The PWM mix is offset by the centre, which is the zero point for silence on the output (Chilly Willy, "32X Audio")COMM[S049-15-centre0].
  • Chilly Willy's player, posted in the Sonic Retro forum thread "Interrupt-Driven DMA PWM on the 32X" (2012), ramps the output from the minimum to the centre first. A source comment says this avoids a click on a real 32XCODE[S046-15-ramp].
  • The release notes of Chilly Willy's MOD player (GenDev forum, March 2011) list "No audio click on start up on real hardware"CODE[S047-15-click].

Techniques#

  • Resample in the mixer. xmplayer is Chilly Willy's player library for XM music files; he posted its mixer source in "32X Audio". The mixer keeps per-voice state: sample pointer, 18.14 fixed-point position and step, volume 0-64 and panCODE[S049-15-struct].
  • Any sample rate. Each voice steps through its samples by that 18.14 increment. In a 2013 post in "32X Audio" Chilly Willy notes that changing the increment lets a sound of any sample rate playCOMM[S049-15-anyrate].
  • Resample on the slave SH-2. Chilly Willy resamples every voice to the mixer rate in software on the slave SH-2, as he explains in "32x sound programming"COMM[S051-15-slave].
  • Double-buffer the output. Mix into the idle half of a buffer while DMA plays the other half; DMA-driven PWM shows the set-up.
