Timings and clocks

This page explains how fast each part of the 32X runs and how the time of one video frame is divided. You need it to budget CPU cycles per line and per frame, to schedule VDP register writes, and to understand why the same game runs slightly slower on a PAL console than on an NTSC one.

Summary#

  • One crystal drives everything. The master clock is 53.693175 MHz on NTSC and 53.203424 MHz on PALDOC[S001-fosc][S005-fosc].
  • The CPUs run from it through fixed dividers. A 68000 clock cycle is 7 master clocks. An SH-2 clock cycle is one third of a 68000 cycleDOC[S001-vclk][S001-sclk].
  • Each SH-2 therefore runs at 3/7 of the master clock: about 23.01 MHz on NTSC and 22.80 MHz on PALDERIVED[S001-sclk].
  • A video line is 100 dots of blank plus 320 dots of picture. An NTSC frame is 38 blank lines plus 224 picture linesDOC[S001-hb-a][S001-hb-b][S001-vb-a].
  • The VDP reads its registers once per line. A write that lands in latch interval C takes effect on that line; a write in interval D takes effect on the next oneDOC[S001-latch-c][S001-latch-d].

Details#

The clock chain#

Every clock on the board is derived from one quartz oscillator, the master clock (written fosc). One period of it is called a master clock, abbreviated Mck. The 68000 and the two SH-2 processors divide it down by fixed ratios, so their speeds always keep the same relationship to each other.

ClockNTSCPALDerivationSource
Master clock (fosc, 1 period = 1 Mck)53.693175 MHz53.203424 MHzquartzDOC[S001-fosc][S005-fosc]
68000 cycle (Vclk)7 Mck7 Mckfosc / 7DOC[S001-vclk][S005-vclk]
SH-2 cycle (Sclk)Vclk / 3Vclk / 33 x fosc / 7DOC[S001-sclk][S005-sclk]
SH-2 frequency23.011361 MHz22.801467 MHz3 x 53.693175 / 7 and 3 x 53.203424 / 7DERIVED[S001-sclk]
68000 frequency7.670454 MHz7.600489 MHz53.693175 / 7 and 53.203424 / 7DERIVED[S001-vclk-f]
PWM cycle-register base clock23.01 MHz22.8 MHzas printed in the manualDOC[S001-pwm-ntsc][S001-pwm-pal]

Released software agrees with these figures:

  • d32xr, the GitHub source of Doom 32X Resurrection (a homebrew rework of Doom for the 32X), stores both SH-2 clocks as constants: 23,011,360 Hz and 22,801,467 HzCODE[S171-ntscc][S171-palc].
  • The same program sets up PWM with 23,011,361 Hz for NTSC, 1 Hz more than its own constant for the same clockCODE[S171-pwmn].
  • Sega Retro, a community wiki about Sega hardware and games, lists the same two SH-2 frequencies, 23.01136 MHz and 22.801467 MHzCOMM[S013-clk].

Sega's development hardware used different crystals for PAL. On the main board the 53.693 MHz crystal was replaced by 53.203 MHz, and on the interface board 46.022 MHz by 45.6 MHzDOC[S002-xtal1][S002-xtal2].

How one video line is divided#

A line is counted in dots. Sega divides it into the parts below, each given in dots and in master clocks.

PartDotsMaster clocks
A: blank period100860
B: picture period3202560
C: from the start of horizontal blank to vertical blank27224
D: from the start of horizontal blank to the display-enable signal (XHDISP)324

These are the manual's valuesDOC[S001-hb-a][S001-hb-b][S001-hb-c][S001-hb-d]DOC[S005-hb].

A line therefore lasts 860 + 2560 = 3,420 master clocks. One SH-2 cycle lasts 7/3 master clocks, so every master clock gives each SH-2 3/7 of a cycle, and each SH-2 gets about 1,466 cycles per line (3,420 x 3/7)DERIVED[S001-hb-a][S001-hb-b][S001-sclk].

How one frame is divided#

A frame is a number of blank lines followed by a number of picture lines. The count depends on the video standard and, on PAL, on whether the 224-line or the 240-line picture is used.

ModeBlank linesPicture lines
NTSC38224
PAL, 224 lines89224
PAL, 240 lines73240

The manual writes these numbers with an "h" suffixDOC[S001-vb-a][S001-vb-b]DOC[S005-vb], but they are decimal line counts: added together they give 262 lines per NTSC frame (38 + 224) and 313 lines per PAL frame (89 + 224 or 73 + 240)DERIVED[S001-vb-a].

The cycle budget of one frame#

Multiplying the line length by the line count gives the length of a frame, and from it the number of cycles each CPU gets per frame. These are the figures to plan a frame's work against.

NTSCPAL
frame length262 x 3,420 = 896,040 Mck313 x 3,420 = 1,070,460 Mck
frame rateabout 59.92 Hzabout 49.70 Hz
SH-2 cycles per frame, each CPUabout 384,017about 458,769
68000 cycles per frameabout 128,006about 152,923

All of the table is arithmetic on the clock and line figures aboveDERIVED[S001-frame].

  • Two SH-2s, two budgets. The master and the slave each get the full SH-2 figure, so a frame offers about 768,000 SH-2 cycles on NTSC if both are kept busyDERIVED[S001-frame2].
  • Bus waits come out of the budget. Every access to the cartridge, the frame buffer or the registers costs wait states on top of the instruction itself; Memory map lists them per region.
  • PAL frames are longer. A PAL frame has about 19% more cycles than an NTSC frame, even though each clock runs about 1% slower, because it has 313 lines instead of 262DERIVED[S001-frame3].

When a VDP register write takes effect#

The VDP does not read its registers continuously. It latches them once per line, shortly after horizontal blank begins. The manual's Figure 3.17 marks four intervals around that point and gives the length of the first three.

IntervalLength
A: horizontal blank to the PEN signal3 dots (24 Mck)DOC[S001-latch-a]
B: width of the FEN signal (the VDP-side DRAM refresh)40 SclkDOC[S001-latch-b]
C: horizontal blank to the latch76 dots (668 Mck)DOC[S001-latch-cw]
D: from the latch to the next line's latchno length printed; the figure draws it across the rest of the lineDOC[S005-latch-fig]

A register written during interval C takes effect on line n. A register written during interval D takes effect on line n+1DOC[S001-latch-c][S001-latch-d]. The manual advises against CPU register writes that overlap the latch itselfDOC[S001-latch-avoid]. FEN reads 1 while the DRAM refreshes, and the DRAM can still be accessed during that timeDOC[S001-fen].

Bus settings the master boot ROM applies to the SH-2#

The SH-2's bus state controller (BSC) sets the bus width and the number of wait states for each memory area. The master boot ROM writes four of its registersCODE[S160-bcr1]. ob1, a member of the GenDev forum, disassembled the boot ROM and decoded the values in the thread "32X memory type" (2020); the table gives ob1's reading.

RegisterValue writtenReading
BCR1$A55A00013 wait states for areas 0 to 3; area 2 is ordinary space, area 3 is SDRAMCODE[S160-bcr1];COMM[S160-3w]
BCR2$A55A00A8areas 0 to 3 are 16 bits wideCODE[S160-bcr2];COMM[S160-16]
WCR$A55A0055no idle cycles for areas 0 to 3; CAS latency 2CODE[S160-wcr];COMM[S160-cas]
MCR$A55A0AB8SDRAM timing and refresh set-up; burst bit off, although the SDRAM bursts regardlessCODE[S160-mcr]
  • Set once. ob1 reports that these settings cannot be rewritten once made, short of a resetCOMM[S160-once].
  • The frame buffer is not on the SH-2 bus directly. ob1 also says the VRAM is not connected to the SH-2s and is reached through a chip ob1 calls "a DAC (315-5781)"COMM[S160-dac].
  • Frame buffer parts. Earlier in the same thread (2009), another forum member, TmEE, identifies them as 80 ns, 1 Mbit fast-page-mode DRAMsCOMM[S160-fpm].

Register meanings are on The SH-2 on the 32X.

Other fixed timings#

  • An auto fill takes 7 + 3 x length cyclesDOC[S005-fill]. The video pages cover it in detail.
  • Bus cycles and wait states per memory region (cartridge, frame buffer, palette, registers, SDRAM) are on Memory map.

Pitfalls#

Do not enable the 240-line mode on an NTSC console. The VDP malfunctionsDOC[S001-240].

  • Sega's own test program, Mars Check, follows this rule. It reads the Mega Drive version register at start-up and writes the 240-line bit only when bit 6 reports PAL: $42 on PAL, $02 on NTSCCODE[S201-240pal][S201-42].

Register writes that meet the line latch behave in a way the manual does not describe. Sega fixes the line by interval (C: line n, D: line n+1) and advises against a write that overlaps the latch itselfDOC[S001-latch-avoid].

  • Mars Check's "3 MODE DISPLAY" test changes the display mode in the middle of the frame, timed by counting lines with the Mega Drive VDP's horizontal interrupt. It writes the 32X bitmap mode byte at counts $10, $50, $90 and $D0CODE[S206-modes].
  • Each write lands on a known line, but at no fixed point in that line relative to the latchCODE[S206-nolatch].

PAL consoles run every 32X clock about 1% slower (22.8 MHz against 23.01 MHz). This shifts every PWM sample rate set by a cycle count and gives each SH-2 about 1% fewer cycles per second; per frame PAL has more cycles, as the budget table above showsDERIVED[S001-pwm-pal2].

  • d32xr computes its PWM cycle register from the clock of the region it runs in. A bit of the display mode register selects between 23,011,361 Hz and 22,801,467 HzCODE[S171-pwmn][S171-pwmp].

Techniques#

  • The per-frame cycle budget is worked out above; SH-2 instruction timings and cache behaviour that decide how much of it real code gets are on SH-2 pipeline and instruction timings and The SH-2 on the 32X.
