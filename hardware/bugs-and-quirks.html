Bugs and quirks

This page is a one-stop index of the known 32X hardware bugs and quirks. Each item names the quirk, the best evidence for it and the page that explains it. Use it to find out quickly whether a problem you meet is known, and where to read more.

Summary#

  • Sega documented several of its own bugs. Its bulletins and manual supplements cover the SH-2 interrupt problem, the VDP shift bit and 68000 interrupts during RV = 1DOC[S070-b27][S070-b14][S070-b09].
  • The 68000-to-SH-2 FIFO DMA loses data. Chilly Willy measured on hardware that a 65,536-word transfer typically lost between 20 and 120 wordsHW[S036-rate].
  • The cartridge is read-only to the SH-2s. With RV = 0, the 68000's LWR# write strobe never asserts either. Charles MacDonald found both in his cartridge signal testHW[S178-none][S178-lwr].
  • RV survives a soft reset. Chilly Willy reports it, and d32xr's start-up code clears RV itselfCOMM[S111-rv];CODE[S088-clrrv].

Details#

The items below draw on a few recurring sources.

  • Sega's 32X Technical Bulletins are numbered notes that Sega's Developer Technical Support sent to Sega and third-party developers between September and December 1994. This page cites bulletins 6, 7, 9, 11, 12, 13, 14, 15, 22, 23 and 27.
  • Sega's Hardware Manual Supplements are correction sheets to the 32X Hardware Manual. Supplement 1 (June 1994) covers the communication ports; Supplement 2 (July 1994) covers the SH-2 interrupt bug and the write buffer.
  • The 32XDK wiki belongs to the 32XDK repository on GitHub. Its "Bugs and quirks" page collects community notes.
  • Mars Check is Sega's own 32X hardware test program.
  • d32xr is the GitHub source of Doom 32X Resurrection, a homebrew rework of Doom for the 32X.
  • The GenDev forum is where most of the hardware reports were posted. Chilly Willy, who wrote the Wolf32X port, posted many of them; Charles MacDonald, ob1 and Ralakimus posted their own hardware tests there.

Pitfalls#

Each item gives one quirk, the strongest evidence for it and the page that explains it.

SH-2 and interrupts#

  • An interrupt can be acknowledged twice when several are in use. Technical Bulletin 27 (December 1994) describes itDOC[S070-b27]. Knuckles' Chaotix ships the fix. The forum member SoullessSentinel showed it in a disassembly of the game's SH-2 code, in the GenDev thread "68K to SH2 DMA FIFO" (2013)CODE[S020-frt]. See Interrupts.
  • Early production SH-2s lack Sega's interrupt fix. Supplement 2 says the first units use an unmodified chipDOC[SP2-pc2]. Mars Check does the FRT bump in its V, H, CMD and PWM handlersCODE[S187-all]. See Interrupts.
  • The SR interrupt mask must stay at 1 or more, never 0. The 32X Hardware Manual, section 5.3, sets this ruleDOC[S001-r1]. See Interrupts.
  • HEN is one bit shared by both SH-2s. HEN enables H interrupts during V blank. The manual says the register holding it is common to the master and the slaveDOC[S001-hen-common]. See System registers.
  • A clear-register write must be read back before RTE. Supplement 2 gives the SH-2 write buffer as the reasonDOC[SP2-wb]. After Burner's shipped code reads the clear register backCODE[S233-ab]. See Interrupts.
  • The FRT set-up is disputed on retail units. Chilly Willy left it out of Wolf32X and no one complained, he wrote in the GenDev thread "DMA to PWM" (2010)COMM[S048-cw]. Mars Check does the bumpCODE[S187-all]. See Interrupts.
  • Both SH-2s writing one SDRAM location can lock the system. The 32XDK wiki's "Bugs and quirks" page reports itCOMM[S009-sd]. See Bus arbitration.

68000, Z80 and the bus#

  • All 68000 interrupts must be off while RV = 1. Technical Bulletin 9 (September 1994) sets this ruleDOC[S070-b09]. d32xr's start-up code masks them around RVCODE[S088-rvints]. See Bus arbitration.
  • With RV = 1, the ROM bytes at $1070-$1073, $2070-$2073 and $3070-$3073 are "not normally read". Technical Bulletin 12 says soDOC[S092-rv], and the 32XDK wiki repeats itCOMM[S009-rv]. Mars Check's RV DMA test expects $1070-$1073 unchangedCODE[S210-exp]. See Bus arbitration.
  • A VRES reset with RV = 1 can leave the Mega Drive side wrong. Technical Bulletin 6 warns of it and says VRES handlers must decide whether to resetDOC[S090-rv]. See Bus arbitration.
  • SH-2 TAS always runs cache-through. It also holds the bus against the other SH-2, Technical Bulletin 23 (November 1994) saysDOC[S093-ct]. See Bus arbitration.
  • Z80 writes to $840000-$9FFFFF and $A15100-$A153FF lock the 68000. Technical Bulletin 15 says this happens on target 2.0B/2.1 and production units, and that Z80 reads are fineDOC[S148-z80]. The 32XDK wiki prints the range as $84000 and calls the bug "supposedly fixed"COMM[S009-z15]. See Revisions and regions.
  • The Z80 bank register must stay outside $000000-$3FFFFF and $840000-$9FFFFF when the Z80 touches the PSG. Technical Bulletin 22 sets this ruleDOC[S153-bank]. Otherwise the 32X can take the access for an adapter accessDOC[S153-mis].
    • It can then pass wrong data or damage its registersDOC[S153-dmg].
    • How often this happens varies between Mega Drive unitsDOC[S153-var].
    • The 32XDK wiki repeats the ruleCOMM[S009-z22].
  • Cartridge FRAM needs RV = 1 to be read or written. Technical Bulletin 7 says so, and calls RV irrelevant for SRAMDOC[S145-fram]. Charles MacDonald's signal test shows that 68000 save RAM writes need RV = 1 all the sameHW[S178-lwr]. See Bus arbitration and Cartridge bank switching.
  • Word-RAM-to-VRAM capture DMA with a Sega CD fetches undefined data. Technical Bulletin 13 reports itDOC[S147-wram]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • An SH-2 write of 1 to FM forces the video side over to the SH-2, mid-access. The 32X Hardware Manual says soDOC[S001-fmsh]. See Bus arbitration.
  • RV is not cleared by a soft reset. Chilly Willy reports it in the GenDev thread "State of RV Flag during Soft Reset" (2023)COMM[S111-rv]. d32xr's start-up code clears RVCODE[S088-clrrv]. See Bus arbitration.
  • With a Sega CD, writing CD program RAM while RV = 1 locks the 68000 until power-off. Chilly Willy reports this from real hardware in the GenDev thread "Limitations in current 32X emulators" (2012)HW[S169-lock]. See Memory map.
  • SH-2 writes to the cartridge area produce no bus cycle. The cartridge, with its save RAM and bank registers, is therefore read-only to the SH-2s. Charles MacDonald's signal test, posted in the GenDev thread "Some 32X cart port questions" (2012), shows itHW[S178-none]. See Memory map.
  • With RV = 0 the 68000's LWR# write strobe never asserts. Save RAM wired to LWR# therefore needs RV = 1, the same test showsHW[S178-lwr]. See Memory map.
  • Cartridge save RAM works on odd bytes only. Chilly Willy's save-RAM code used even bytes and passed on emulators but failed on a real 32X. He reports this in the GenDev thread "Accessing SRAM" (2009)HW[S182-odd]. See Memory map.
  • The SH-2 faults on word accesses to odd addresses, which emulators of the time let through. Chilly Willy reports it in the GenDev thread "Notice on differences between emulator colors for 32x" (2012)COMM[S170-odd2]. See The SH-2 on the 32X.
  • A Mega Everdrive Pro flash cart returned wrong bytes at a few cartridge addresses. Ralakimus found it at $210000, $210001 and $2130D0-$2130DF, in the GenDev thread "Invalid data being read from specific ROM addresses by the 68000?" (2024 to 2026)HW[S110-bad].
    • Ralakimus saw it on several Genesis and 32X units, and other flash carts did not do itHW[S110-edp].
    • A 2026 firmware update fixed itHW[S110-fix].
  • Interface chip 315-5818 can cause rare SH-2/68000 communication errors. Technical Bulletin 11 says such errors "seldom occur" with the 315-5818, which shipped in products alongside the 5818ADOC[S091-err]. Sega asked for final checks on a 5818A unitDOC[S091-err]. See Revisions and regions.

DMA and communication#

  • FIFO DMA drops words. Chilly Willy measured on hardware that a 65,536-word transfer typically lost 20 to 120 words. He posted the figure in the GenDev thread "Super VDP" (2012)HW[S036-rate]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • FIFO words written while 68S = 0 are not seen by the SH-2, and $A15112 reads 0. ob1 tested this on real hardware, in the GenDev thread "DREQ_FIFO Register" (2022)HW[S112-68s][S001-r5112]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • Keep CHCR0's mode bits ($44E0) when clearing TE. Knuckles' Chaotix does this in its shipped code, as SoullessSentinel's disassembly showsCODE[S020-44e0]. TapamN, another forum member, translated that handler into pseudo-C in the same threadCODE[S020-tap0]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • Sega's CD-mode DREQ path does not work. Chilly Willy reports this in the "Super VDP" thread (2014)COMM[S036-cdmode]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • The SH-2 DMA-end interrupt (CHCR IE) may not fire on a 32X. ob1 saw no interrupt on a real PAL console, in the GenDev thread "DMA DEI" (2021)HW[S180-ob1]. Chilly Willy's DMA PWM player relies on it; he posted it in the GenDev thread "Interrupt driven DMA PWM audio" (2012)CODE[S183-18e5]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • Mars Check's own DMA tests overwrite the program's code. They pass on hardware only because the code runs from the SH-2 cache, notaz, the author of the PicoDrive emulator, explains in a comment on its issue #96 on GitHub (2019)COMM[S179-cache]. The ROM's DMA table asks for twice the SDRAM sizeCODE[S235-found]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • A delay between setting 68S and the first FIFO write seems to be needed. ob1 found 11 NOPs "the bare minimal" on the Kega Fusion and GensKMod emulators, in the GenDev thread "DMA DREQ delay" (2021)EMU[S181-nops].
    • ob1 writes that the delay "might be needed" for the DREQ circuitEMU[S181-might].
    • d32xr waits for an SH-2 handshake insteadCODE[S088-hs]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC).
  • A communication word read during the other side's write can be wrong. Supplement 1 says the write always lands but the read may be wrong, and that byte-split words are safeDOC[SP1-rd]. d32xr keeps one writer per wordCODE[S171-cmd]. See Communication ports.
  • The Sega CD start marker is "_CD_". The boot ROM flow chart in Sega's R4 manual (July 1994) tests comm0 for itDOC[S005-f-cd]. Chilly Willy's start code writes it and was tested on a real CD32X; he posted it in the GenDev thread "Starting the 32X from Sega CD" (2012)HW[S019-cd]. See Boot, security and ROM headers.

VDP-side items#

These rules come from the 32X Hardware Manual unless another source is named.

  • The shift bit fails when a line table entry's low byte is $FF. Technical Bulletin 14 reports itDOC[S070-b14]. See Screen shift (1-pixel horizontal scroll).
  • SH-2s must not touch the frame buffer while auto fill runsDOC[S001-fillnoacc]. See Auto fill (VDP frame buffer fill).
  • Byte writes of 0 to the frame buffer are ignoredDOC[S001-zero]. Mars Check's byte-write test expects thisCODE[S188-bw]. See Memory map.
  • A DRAM mirror sits at $24040000, the 32XDK wiki reportsCOMM[S009-mirror]. See Memory map.
  • The 240-line mode on an NTSC console makes the VDP malfunctionDOC[S001-240]. Mars Check sets the 240-line bit only on a PAL unitCODE[S201-240pal]. See Timings and clocks.
  • Avoid a VDP register write that overlaps the per-line register latch. The manual does not say what such a write doesDOC[S001-latch-avoid]. Mars Check's mid-frame mode writes land on known lines, but at no fixed point against the latchCODE[S206-modes][S206-nolatch]. See Timings and clocks.
  • The palette accepts word accesses only, from both sidesDOC[S001-3.1pal]. Every palette access in Mars Check is a word or a longword, on the SH-2 and on the 68000CODE[S188-palsh][S188-pal68]. See Memory map.
  • System and VDP registers must be accessed through cache-through addressesDOC[S001-3.4ct]. See Memory map.

PWM sound#

  • A write to a full PWM FIFO discards the oldest entryDOC[S001-p-old]. See PWM sound (registers, cycle, FIFO).
  • A pulse-width register read returns undefined data in bits 11 to 0. Only FULL and EMPTY are meaningfulDOC[S001-p-und]. Every pulse-width read in Mars Check tests only bit 15 or bit 14CODE[S189-pw]. See System registers.
  • Output that starts at 0 instead of the centre value clicks on a real 32X. Chilly Willy's DMA PWM player ramps up to the centre first, and its comment names the real 32X. He posted it in the Sonic Retro forum thread "Interrupt-driven DMA PWM on the 32X" (2012)CODE[S046-ramp]. See Software mixing for PWM.

Techniques#

Workarounds live on each topic page: unified interrupt handler (Interrupts), FIFO transfer procedure (DMA (68000 to SH-2 FIFO, SH-2 DMAC)), byte-split communication words (Communication ports).

Where sources disagree#

  • Interrupt set-up. See Interrupts for the three disputes.
    • In the GenDev forum thread "DMA to PWM" (2010), Chilly Willy and another forum member, Snake, dispute whether the timer workaround is needed on retail units.
    • The 32XDK wiki and Sega's Supplement 2 differ on which SH-2 chip revision has the bug.
    • Sega's manual and Sega's own sample program use different FRT start values.
  • Cartridge area. The printed end of the fixed ROM window and the behaviour of SH-2 accesses while FM = 0 differ between manual sections; see Memory map.
  • Other disagreements are listed on where sources disagree, and untested ideas on Open questions.

Open questions#

  • What does a VDP register write that overlaps the per-line register latch do on a retail console? The manual only says to avoid it.
  • Does the SH-2 DMA-end interrupt fire on an NTSC 32X? ob1's test that saw none was on a PAL console.
