Boot, security and ROM headers

This page follows a 32X from power-on to the first line of your game. It covers what the 68000 and the two SH-2 boot ROMs do, and what the cartridge header must contain. It also explains the security check and how a Sega CD starts the 32X. You need it to build a bootable cartridge or CD image, or to understand why a console refuses to start.

Summary#

  • Power-on. Sega's 32X Hardware Manual describes the start in section 3.1. The 68000 runs the cartridge like a plain Mega Drive. Sega's initial program in the cartridge sets ADEN (32X enable) to 1, initialises the hardware and starts the applicationDOC[S001-3.1a].
  • The initial program (ICD_MARS.PRG) must sit unchanged at cartridge $3F0. The 32X boot ROM checks it, and a mismatch locks the 32XDOC[S001-sec-3f0][S001-sec-lock]. The same manual also says 3FAh elsewhere; see the disagreements below.
  • The two SH-2s run different boot ROMs. They sleep until the 68000's initial program wakes them, and the master runs the security checkDOC[S001-5.1boot].
  • Initial data. The master then copies the "initial data" from cartridge to SDRAM, as set by the user header at cartridge $3C0DOC[S001-5.1boot][S001-5.1hdr].
  • Handshake. Before the application starts, the master writes "M_OK" and the slave "S_OK" to the communication ports. The 68000 must clear them, and the SH-2s wait for thatDOC[S001-5.1sync][S001-5.1clear].

Details#

Offsets on this page are cartridge ROM offsets. With ADEN = 1 the 68000 sees cartridge offset $000000 at $880000 (see Memory map)DOC[S001-3.5a].

Cartridge layout for the boot#

The "Startup" page of the 32XDK repository wiki on GitHub warns that the Genesis/Mega Drive header and the 32X header must both be right, or the system does not bootCOMM[S007-hdr].

32X ID and territory lockout#

Sega's Developer Technical Support sent numbered 32X Technical Bulletins to Sega and third-party developers in 1994. Bulletin 28 (November 29, 1994), "32X ID Data/Territory Lockout", sets what the header must carry: a 32X identification string and a one-digit code that enables or disables regions.

Cartridge offsetContentsSource
$100-$10F"SEGA 32X" padded with spaces: ASCII 53 45 47 41 20 33 32 58, then 20 to $10FDOC[S094-id][S094-ascii]
$110-$1EFas on a Genesis/Mega Drive cartridgeDOC[S094-same]
$1F0one ASCII hex digit: the hardware enable data; $1F1-$1FF filled with spacesDOC[S094-1f0]

The bulletin's table for the digit enables four territories, written J, S, U and E.

  • What J, S, U and E are. They are the four $A10001 bit 7 and bit 6 settings: Japan NTSC, Japan PAL, overseas NTSC, overseas PALDOC[S094-tab].
  • Digits that enable each territory. J: 1, 3, 5 and so on. S: 2, 3, 6, 7, A, B, E, F. U: 4 to 7 and C to F. E: 8 to F.
  • So the digit is a bit mask. Bit 0 = J, bit 1 = S, bit 2 = U, bit 3 = EDERIVED[S094-tab].
  • Sega's own examples agree. "F" is for all territories, "4" for US-onlyDOC[S094-f][S094-us].
  • Territories. J is Japan, South Korea and Taiwan. S is selected Asian regions. U is North America and Brazil. E is Europe and Hong KongDOC[S094-terr].
  • Consequence. An error in this data meant the software was not releasedDOC[S094-rel].

MARS user header ($3C0)#

The user header tells the boot ROM what to copy from the cartridge to SDRAM and where each SH-2 starts. The field order below follows Sega's example listing in section 5.1 of the manual.

FieldExample valueSource
module name, 16 characters'MARS CHECK MODE 'DOC[S001-h-name]
version (long)$0DOC[S001-h-ver]
source address (long): byte offset in the cartridge, 0 = ROM start$0000C000DOC[S001-h-src][S001-h-srcdef]
destination address (long): byte offset in SDRAM, 0 = SDRAM start$0DOC[S001-h-dst][S001-h-dstdef]
size (long): bytes, a multiple of 4$00004000DOC[S001-h-size][S001-h-mul4]
master SH-2 start address (long)$06000120DOC[S001-h-mst]
slave SH-2 start address (long)$06002000DOC[S001-h-sst]
master SH-2 vector base address (long)$06000000DOC[S001-h-mvbr]
slave SH-2 vector base address (long)$06002000DOC[S001-h-svbr]

Rules for the header values:

  • Alignment. The boot ROM copies in long words, so source and destination must be long-word alignedDOC[S001-h-align].
  • Entry points. The start and vector base addresses must be aligned too, or the SH-2 takes an address errorDOC[S001-h-align2].

The header ends at $3F0, where the initial program begins.

  • Sega's R4 manual (July 1994), page 80, gives the range as $3C0 to $3F0, with "3EDh" struck through and "3F0h" printed beside itDOC[S005-hdr].
  • marsdev, a Mega Drive and 32X toolchain on GitHub, has a working header of the same shape: a 16-character name, then eight long words. The 68000 code follows it directly "at 0x3F0"CODE[S061-hdr][S061-3f0].

Start-up rules from Sega's bulletins#

Four more of Sega's 32X Technical Bulletins set start-up rules: bulletin 30 (stacks), 24 (region read), 29 (32X detection) and 33 (backup RAM). Bulletin 24 is dated September 23, 1994; the other three, December 8, 1994.

TopicRuleSource
SH-2 stacks at start (bulletin 30)r15 is $06040000 on the master and $0603F800 on the slave. To change them, set r15 at the start of the program, because changing the vectors does not do it.DOC[S158-sp][S158-sl][S158-vec]
region and TV standard (bulletin 24)Read $A10001 after power-on or reset. Ignore the value ICD_MARS.PRG leaves in D1, because a reset during its checksum (about 2 s on a 24 Mbit cartridge) loses it.DOC[S154-read][S154-2s][S154-d1]
32X absent (bulletin 29)Sega's dual-mode sample returns from the initial program with an error flag when no 32X is present and branches to a Genesis-only mode.DOC[S157-rec][S157-err]
Sega CD backup RAM (bulletin 33)Set RV = 1 before calling the CD boot ROM backup routines, and before returning to the Control Panel.DOC[S159-bk][S159-cp]

ob1, a member of the GenDev forum, posted disassemblies of both SH-2 boot ROMs there. His slave boot ROM disassembly, in the thread "32X Slave SH2 BIOS disassembly" (2021), defines the same slave stack $0603F800CODE[S117-sp]. The master stack value matches his master boot ROM disassembly below.

SH-2 boot ROM flow#

Each SH-2 runs its own boot ROM. The table lines up the steps of the two. "comm0", "comm4" and "comm8" are the communication ports at byte offsets 0, 4 and 8DOC[S001-f-comm] (see System registers).

StepMaster SH-2Slave SH-2Source
1registers, bus state controller, SDRAM mode set upregisters, bus state controllerDOC[S001-f-m1][S001-f-s1]
2sleep until the 68000 initial program wakes the 32XsleepDOC[S001-f-msleep][S001-f-ssleep]
3cache clear, cache oncache clear, cache onDOC[S001-f-mcache][S001-f-scache]
4SDRAM test; on failure "SDER" to comm0; else clear SDRAMwait for a cartridgeDOC[S001-f-sder][S001-f-scart]
5cartridge check, then security; on failure "SQER" to comm0; else checksum to comm8wait for comm0 = "_CD_" or "M_OK"DOC[S001-f-sqer][S005-f-swaitcd][S001-f-swait]
6if comm0 = "_CD_": checksum to comm8DOC[S005-f-cd]checksum to comm8DOC[S001-f-scs]see the cited flow charts
7load the initial data, cartridge to SDRAMwait for comm0 = "M_OK"DOC[S001-f-mload][S001-f-swait2]
8"M_OK" to comm0, start the application"S_OK" to comm4, start the applicationDOC[S001-f-mok][S001-f-sok]

Inside the master boot ROM (disassembly)#

In the GenDev forum thread "Master SH2 BIOS" (2007), ob1 posted a disassembly of the master SH-2 boot ROM. It shows the followingCODE[S018-src].

DetailWhat the code doesSource
reset stackpower-on and manual reset SP = $06040000CODE[S018-sp]
checksumsums the cartridge words up to the end-of-ROM address in the header, if the header checksum is non-zeroCODE[S018-cs][S018-nz][S018-start][S018-end]
reportwrites the sum to GBR + $28, the word Sega's flow chart calls comm8CODE[S018-comm8]
loadreads the user header from SH-2 $220003D4 (the source-address field, seen cache-through) on, to copy the initial data to SDRAMCODE[S018-hdr]

The checksum addresses are cache-through SH-2 addresses. Subtracting $22000000, the cache-through cartridge base, gives the cartridge offset.

  • The code reads the header checksum word at SH-2 $2200018E, cartridge offset $18EDERIVED[S018-cs][S001-shrom].
  • It sums only when that word is non-zeroCODE[S018-nz].
  • The sum starts at SH-2 $22000200, cartridge offset $200DERIVED[S018-start][S001-shrom]. It ends at the address held in the header's end-of-ROM field, read at SH-2 $220001A4, cartridge offset $1A4DERIVED[S018-end][S001-shrom].

Sega CD + 32X boot handshake#

With a Sega CD there is no 32X cartridge ROM to load from, so the header and all code and data are copied into the 32X frame buffer insteadCOMM[S007-cd-fb]. The 32XDK wiki, the community-written wiki for 32X developers on GitHub, gives the sequence below on its "SegaCD" pageCOMM[S007-cd-md1].

StepCPUActionSource
1Mega Drive 68000look for the 32X signature; if present, turn the 32X on and tell the Sega CD through its communication registerCOMM[S007-cd-md1]
2CD 68000wait for that; load the 32X start code from CD into word RAM, give word RAM to the Mega Drive side, and signal readyCOMM[S007-cd-cd]
3Mega Drive 68000wait; take the 32X VDP (FM), copy word RAM to the 32X frame buffer, release the VDPCOMM[S007-cd-copy]
4Mega Drive 68000write "_CD_" to the 32X communication register and wait for "M_OK" / "S_OK"COMM[S007-cd-done]

The Sega manual's boot flow has the matching branch: both SH-2 boot ROMs test comm0 for "_CD_"DOC[S005-f-cd][S005-f-swaitcd]. In ob1's disassembly of the slave boot ROM, the CD path reads the start data from the frame bufferCODE[S117-fb].

In the GenDev forum thread "Starting the 32X from Sega CD" (2012), the forum member Chilly Willy posted start code that does it this way on the Mega Drive 68000. He reports it tested on a real CD32XHW[S019-hw]. The Sega CD side cannot reach the 32X, so it hands code and data to the Mega Drive sideHW[S019-cd].

StepActionSource
1read $A130EC; continue only if it holds "MARS"HW[S019-mars]
2interrupts off; with a0 = $A15000, write 1 to the byte at $0101(a0), the adapter control low byte (32X on, SH-2s held in reset); wait about 10 msHW[S019-aden][S019-base][S019-wait]
3clear comm0 and comm4; write 3 to $0101(a0) to release the SH-2 resetHW[S019-res]
4take the 32X VDP (clear FM, bit 7 of $0100(a0), until it reads 0); clear registers, both frame buffers, paletteHW[S019-fm]
5if comm0 reads "SDER", stop: the master's SDRAM test failedCODE[S019-sder]
6copy the SH-2 code and data to the frame buffer at $840000HW[S019-copy]
7write "_CD_" to comm0; wait for "M_OK" in comm0 and "S_OK" in comm4HW[S019-cdmark]
8write 0 to comm0 and comm4 to start the master and the slaveHW[S019-go-m][S019-go-s]

The SH-2 program must be built to run from SDRAM, since there is no cartridgeCOMM[S019-sdram].

Security#

The boot ROM confirms that the initial program is present at its place. If the contents do not match, the 32X locks and the Mega Drive side cannot access itDOC[S001-sec-lock]. A changed initial program, or one not entered from its start, cannot be releasedDOC[S001-sec-rel][S005-sec].

In 2007 ob1 reverse engineered the initial program and posted the results in the GenDev forum thread "32x 'security code' reverse engineered".

  • ob1 reads it as mostly test and initialisation, with few real security checksCOMM[S116-sec].
  • It switches the 32X on from 68000 RAM, because setting ADEN remaps the cartridge under the running codeCOMM[S116-aden][S116-ram].
  • The master boot ROM checks the copy of the initial program in the cartridge, at $36C-$76C in the ROM he examinedCOMM[S116-chk][S116-range].

Pitfalls#

Sega's manual gives two offsets for the initial program: "3FAh or more" in section 3.1DOC[S005-3fa] and "(address 3F0h) without change" in section 5.2DOC[S005-3f0]. marsdev places the code at $3F0CODE[S061-3f0]. Use $3F0.

The CD marker is "_CD_", with an underscore at each end.

  • The boot ROM flow chart in Sega's R4 manual (July 1994), page 81, tests comm0 for "_CD_"DOC[S005-f-cd].
  • The 32XDK wiki's SegaCD page writes "_CD_" tooCOMM[S007-cd-done].
  • Chilly Willy's start code, tested on a real CD32X, writes "_CD_"HW[S019-cdmark][S019-hw].

The SH-2s wait for the 68000. They keep waiting until the 68000 clears "M_OK" / "S_OK"DOC[S001-5.1clear]. Working start code clears both words to start the SH-2sHW[S019-go-m][S019-hw].

Boot error codes land in comm0: "SDER" (SDRAM test failed) and "SQER" (security failed)DOC[S001-f-sder][S001-f-sqer]. Chilly Willy's start code checks comm0 for "SDER"CODE[S019-sder].

Techniques#

Working headers and start code to copy from are in marsdev and on the toolchain pages, for example Devkits (Chilly Willy's devkit, marsdev).

Where sources disagree#

  • Where the initial program sits. 3FAh or 3F0h; see the pitfalls above and Devkits (Chilly Willy's devkit, marsdev).
