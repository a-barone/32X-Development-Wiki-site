Shipped-code survey: what 32X ROMs do with the registers

Shipped 32X code ran on real consoles, so it shows how the registers were used in practice. This page counts, register family by register family, how many of 39 32X ROMs contain a given access, and names routines that show it. The 39 are 29 retail games, 3 prototypes, an ECCO the Dolphin CinePak developer demo and 6 Sega SDK programsDERIVED[S230-set]. The SDK programs are Mars Check (Sega's 32X hardware test program) in two sets, and four Mars sample programsDERIVED[S230-set]. Use it to see how common a practice is before you rely on it.

Summary#

  • Auto fill. 14 of the 39 ROMs hold SH-2 code that writes the fill length, start or data register (64 sites)CODE[S230-total].
  • Frame buffer control. 19 of the 39 access the frame buffer control register (FEN, FS) from the SH-2 (66 sites)CODE[S231-total].
  • Bitmap mode. 3 of the 39 write the bitmap mode or screen shift register from the SH-2 (14 sites)CODE[S232-total].
  • Interrupt clear read-back. 22 of the 39 write an interrupt clear register and read it back at once (150 sites at most)CODE[S233-total].
  • Region. 31 of the 39 hold the version register $A10001 as a 68000 operand (63 sites)CODE[S234-total].
  • Divider and bank registers. 17 of the 39 start the SH-2 dividerCODE[S236-divu]; 5 address the Mega Drive register $A130F1CODE[S236-bank].

Details#

Results by register family#

Each count is a byte-pattern count: the places where a ROM holds the instruction pattern of that access. For the VDP registers the pattern is an SH-2 load of the VDP register base $20004100 from a literal pool, followed by a register accessCODE[S230-method]. A constant can also sit in data, so some sites may not be code and every count is an upper boundCODE[S233-total].

"Sites" counts matching places; "ROMs" counts the ROMs among the 39 that have at least one.

Auto fill and the frame buffer#

FEN (bit 1 of the frame buffer control register) reads 1 while frame buffer access is denied because a fill is runningDOC[S001-fen]. FS (bit 0) selects which of the two frame buffers is shownDOC[S001-fs]. The routines below show how shipped games wait on these bits.

  • Virtua Racing Deluxe waits for each fill to end. Its fill loop writes the length, start and data registers, then polls the frame buffer control register with tst #2 until bit 1 (FEN) is 0 before the next fillCODE[S230-vrd].
    • The next fill is programmed only after the hardware reports the last one done.
  • Star Wars Arcade waits before it programs a fill. One routine polls FEN until it is 0, and only then reads the fill start register, adds 95 and writes the start, length and data registersCODE[S230-swa].
    • Waiting first keeps the routine off the fill registers while an earlier fill still runs.
  • Star Wars Arcade flips the frame in three steps. A short routine does all threeCODE[S231-swap].
    • It polls the frame buffer control register with tst #2 until bit 1 (FEN) is 0.
    • It reads the register, XORs bit 0 (xor #1) and writes it back.
    • It then re-reads it until bit 0 equals the written value.
    • Together this is a complete frame swap: wait until the VDP is free, toggle FS, then confirm that the swap has taken effect.
  • T-Mek sets the bitmap mode from the SH-2. It loads #1 into r0 and writes it to the bitmap mode register with mov.w r0,@(0,r14)CODE[S232-mode]. The other two ROMs with SH-2 mode writes are NBA Jam Tournament Edition and Virtua Racing DeluxeCODE[S232-total].
    • So a shipped game can set the display mode from the SH-2 side, not only from the 68000.

Fill loops are on Auto fill (VDP frame buffer fill), and the register layout is on System registers.

Interrupt clear registers#

34 of the 39 ROMs load GBR with the SH-2 system register base $20004000CODE[S233-armed]. The read-back after a clear write is common practice:

  • After Burner writes the VRES clear register at $20004014 through GBR and reads it back on the next instructionCODE[S233-ab].
  • Golf Magazine 36 Great Holes does the same at the entry of a handlerCODE[S233-golf].
  • Mars Check differs between its two sets. Set 2 writes the V interrupt clear register at $20004016 and reads it back later in the routineCODE[S233-mc2]. Set 1's handlers do not read it backCODE[S233-mc1].

Why the read-back matters is on Interrupts.

Region checks#

  • BC Racers reads $A10001, shifts the byte right by 6, masks it with 3 and compares the result with 0 and 1CODE[S234-bc].
  • Doom does the same read, shift and mask, then indexes a table with the result and branches on the entryCODE[S234-doom].

Bits 7 and 6 of the version register are the region bits; see Revisions and regions.

Sega's ROM-to-SDRAM DMA test#

  • The Mars Check parameter table holds the destination $06020000 and the count $8000.
  • The table's channel control value $5EE1 selects the 16-byte unit, so that is 524,288 bytes against 256 KB of SDRAMDERIVED[S235-der].
  • The table occurs four times in the Set 1 ROMCODE[S235-found]. See DMA (68000 to SH-2 FIFO, SH-2 DMAC) and Test ROMs: Sega's Mars Check Program.

Pitfalls#

Code can reach the registers through GBR instead of a literal pool. Sega's Mars Check loads GBR with $20004000 and reaches its interrupt clear registers through @(disp,gbr) formsCODE[S187-gbr]. Such accesses are not in the VDP counts above, which take only the literal-pool form.

Most bitmap-mode writes come from the 68000 side. The SH-2 count of 3 ROMs is not a count of games that change modesCODE[S232-68k].

Open questions#

  • Which SH-2, master or slave, runs each routine above? A trace on hardware, or an emulator that labels the CPU, would settle it.
  • How many shipped games reach the fill, frame buffer and mode registers through GBR or from the 68000 side?
