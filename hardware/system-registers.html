System registers

The 32X adds a block of control registers that both the 68000 and the two SH-2 processors can see, each at its own address. This page lists every register, its address on each side, what its bits mean and which mistakes are easy to make. You need it whenever you switch the adapter on, hand the video chip from one CPU to the other, raise interrupts across CPUs, or start a DMA transfer between them.

Summary#

  • Two register sets, one per CPU. The 68000 sees them at $A15100DOC[S001-r5100]. The SH-2s see their own set at $20004000, through the cache-through mirrorDOC[S001-r4000]. The two lists are not identicalDOC[S001-3.2list].
  • Only the 68000 has: adapter control (switching the 32X on, resetting the SH-2s, handing over the video chip), the command that interrupts the SH-2s, and the cartridge bank switchDOC[S001-3.2list].
  • Only the SH-2s have: the interrupt mask (which holds its own copy of the FM and ADEN bits), the H-interrupt interval, the standby register and the five interrupt-clear registersDOC[S001-3.2list].
  • Both sides have: the DMA-request (DREQ) registers, the 8 communication words and the PWM sound registers, at different addressesDOC[S001-3.2list].
  • One register is off limits. The register at $A1511A is reserved for Sega's own TV product. The manual says other software must not use itDOC[S001-r511a][S001-tv-no].
  • Cache-through only. Read the SH-2 registers only through the cache-through addresses ($2000xxxx)DOC[S001-3.4ct].

Details#

The tables below show addresses by CPU side. SH-2 addresses are the cache-through view ($2000xxxx): a mirror of the register block that bypasses the SH-2 cache, so a read always reaches the real register. The cached view of the same block is listed on Memory map, but these registers must not be accessed through it.

Adapter control, $A15100 (68000 side)#

This register switches the 32X on and resets the SH-2s. It has four fields. Bits 14 to 8 and 6 to 2 are unused.

Bit1514-876-210
FieldFM-REN-RESADEN

The layout is given by the manualDOC[S001-a-bits][S001-a-fields].

The bit numbers count within the word. Byte code needs the byte view instead: the 68000 is big-endian, so the even byte holds bits 15 to 8 and the odd byte holds bits 7 to 0.

  • Byte view: FM is bit 7 of the byte at $A15100, and ADEN is bit 0 of the byte at $A15101DERIVED[S001-a-byte].

Sega's Mars Check test takes FM from the 68000 side by writing the byte $80 to the adapter control registerCODE[S189-fm68].

  • FM (VDP access). 0 = the Mega Drive owns the video chip (initial value), 1 = the SH-2s own itDOC[S001-a-fm].
  • REN (SH-2 reset enable). 0 = disabled, 1 = enabledDOC[S001-a-ren].
  • RES (SH-2 reset). 0 = reset the SH-2s, 1 = cancel the reset. The initial program sets it, and the manual does not allow changing it afterwardsDOC[S001-a-res].
  • ADEN (32X enable). 0 = 32X off, 1 = 32X on. Like RES, it is set by the initial program and must not be changed afterwardsDOC[S001-a-aden].

Interrupt control, $A15102 (68000 side)#

The 68000 uses this register to send a command interrupt to either SH-2. Bits 15 to 2 are unused.

Bit15-210
Field-INTSINTM
  • INTS. Writing 1 raises a command interrupt on the slave SH-2DOC[S001-i-ints].
  • INTM. Writing 1 raises a command interrupt on the master SH-2DOC[S001-i-intm].

The manual states: "Both are automatically cleared if SH2 does not interrupt clear."DOC[S001-i-clr] The sentence does not say when or how the bits clear. Shipped code shows how Sega's own developers used the bits. SoullessSentinel disassembled Knuckles' Chaotix and posted the relevant code in the GenDev forum thread "68K to SH2 DMA FIFO" (2013):

  • The 68000 code of Knuckles' Chaotix sets INTM and then waits for the bit to read 0. In byte terms INTM is bit 0 of $A15103CODE[S020-intm][S020-src].
  • The Chaotix SH-2 command handler writes the CMD interrupt clear register earlyCODE[S020-clr].

Bank set, $A15104 (68000 side)#

The 68000 normally sees the cartridge ROM through a fixed window. The bank set register chooses which 1 MB of the cartridge appears in the window at $900000 to $9FFFFF. Only bits 1 and 0 (BK1 and BK0) are usedDOC[S001-bk-bits].

DREQ control, $A15106 (68000 side) and $20004006 (SH-2 side)#

DREQ is a DMA request: the mechanism by which the 68000 pushes data to the SH-2 through a small FIFO (first-in, first-out queue). This register controls it. The two sides see different bits.

Bit68000 sideSH-2 sideSource
15unusedFULL (read only): 1 = no space leftDOC[S001-d-sh-bits][S001-d-sh-full]
14unusedEMPTY (read only): 1 = no dataDOC[S001-d-sh-empty]
7FULL (read only): 0 = can write, 1 = cannot writeunusedDOC[S001-d-md-bits][S001-d-md-full]
268S (read/write): 1 = CPU write, meaning the 68000 writes data into the FIFO68S (read only)DOC[S001-d-68s][S005-r4006]
0RV (read/write): 1 = ROM-to-VRAM DMA allowed; SH-2 cartridge access waitsRV (read only)DOC[S001-d-rv][S001-3.1rvro]
  • 68S starts the transfer when set. Writing 0 ends it by force. The bit returns to 0 by itself when the DMA endsDOC[S001-d-68s-run][S001-d-68s-end].
  • RV and ROM-to-VRAM DMA. The 1994 revision of the manual adds that RV must be 1 when doing a ROM-to-VRAM DMADOC[S005-rv-dma].
  • Two names for the FIFO. The 32X Hardware Manual labels the SH-2 side's FULL and EMPTY bits "Frame Buffer, Write Cache"DOC[S001-d-sh-full]. The 68000 side's FULL bit is labelled "DMA FIFO Full"DOC[S001-d-md-full].
    • Sega's interrupt sample program in Supplement 2 calls the high byte of this register, which holds these two bits, "Frame Buffer FIFO Condition". The low byte is "DREQ Control"DOC[SP2-vdpfifo].
    • With the manual's label, that points to the 4-word frame buffer write FIFO rather than the DREQ FIFO.

How DREQ is used in practice is on DMA (68000 to SH-2 FIFO, SH-2 DMAC).

Sega TV register, $A1511A (68000 side)#

This register exists for Sega's own TV product. Bit 0, CM (cartridge mode), selects 0 = ROM (initial value) or 1 = DRAMDOC[S001-tv-cm]. The manual says: "This is a SEGA TV exclusive register; use of this bit with other applications is prohibited"DOC[S001-tv-no]. Leave the register alone.

Communication ports#

  • The ports are eight 16-bit words that both CPUs can read and writeDOC[S001-c-8w].
  • If both CPUs write the same word at the same moment, its value is undefinedDOC[S001-c-und].
  • Usage patterns are on Communication ports.

Interrupt mask, $20004000 (SH-2 side)#

This register decides which interrupts an SH-2 accepts. It also carries two copies of bits that belong to the adapter control register. Bits 14 to 10 and 6 to 4 are unused.

Bit1514-109876-43210
FieldFM-ADENCARTHEN-VHCMDPWM

Bit layout as printed in the manualDOC[S001-m-bits][S001-m-fields].

  • FM. VDP access: 0 = Mega Drive (initial value), 1 = SH-2DOC[S001-m-fm].
  • ADEN. 0 = use of the 32X prohibited, 1 = allowedDOC[S001-m-aden].
  • CART (read only). 0 = cartridge inserted, 1 = not insertedDOC[S001-m-cart].
  • HEN. Whether H interrupts are allowed during vertical blank: 0 = not allowed (initial value), 1 = allowedDOC[S001-m-hen].
  • V, H, CMD, PWM. One enable bit per interrupt: 0 = masked (initial value), 1 = enabledDOC[S001-m-v][S001-m-h][S001-m-cmd][S001-m-pwm].

Both SH-2s use the same addressDOC[S001-m-same]. The V, H, CMD and PWM bits are separate for the master and the slaveDOC[S001-m-sep]. The other bits are sharedDOC[S001-m-common].

H count, $20004004 (SH-2 side)#

  • Meaning. It sets the H-interrupt interval in lines. 0 means every line (initial value)DOC[S001-hc][S001-hc0].
  • When it applies. A new value takes effect only after it is loaded into the internal counter at the end of an H blankDOC[S001-hc-late].
  • Consequence. An H interrupt can still follow the old value.

Interrupt clear registers and levels (SH-2 side)#

Each of VRES, V, H, CMD and PWM has a write-only clear register (see the SH-2 table above). The manual says two different things about an interrupt that is not cleared:

  • It will not occur againDOC[S001-clr-no].
  • Elsewhere it "continues indefinitely until cleared"DOC[S001-clr-cont].

The two statements disagree; see where sources disagree.

Each interrupt has a fixed SH-2 priority level. The mask bit is the bit of the interrupt mask register that enables it.

The 1994 manual gives the same levelsDOC[S005-lvl]. Interrupt behaviour and the SH-2 interrupt bug are on Interrupts.

PWM registers#

The PWM (pulse-width modulation) registers drive the 32X sound output. This section only lists their bits; the full description is on PWM sound (registers, cycle, FIFO).

RegisterBitsSource
controlbits 11-8 TM3-0, bit 7 RTP, bits 3-0 RMD0, RMD1, LMD0, LMD1DOC[S001-p-bits][S001-p-fields]
pulse widthbit 15 FULL, bit 14 EMPTY (both read only), bits 11-0 the pulse widthDOC[S001-p-pwf]
  • TM3-0 set the timer interrupt interval. The SH-2 sets them; the 68000 can only read themDOC[S001-p-tm].
  • TM = 1 gives one interrupt per cycle-register periodDOC[S001-p-tm1].
  • TM = 0 gives one interrupt every 16 cycle-register periodsDOC[S001-p-tm0].
  • RTP enables DREQ1 requests. It is set on the SH-2 side only and is read only from the 68000DOC[S001-p-rtp].
  • The cycle register counts in Scyc, one period of the PWM base clock. The base clock is 23.01 MHz on NTSC and 22.8 MHz on PAL, and the cycle is the set value times ScycDOC[S001-p-ntsc][S001-p-pal].
  • The pulse width is the value in bits 11-0 times ScycDOC[S001-p-pw].

The 68000 cannot read the PWM registers on development target Ver. 1.0; Ver. 2.0 canDOC[S002-pwm].

Pitfalls#

The FIFO register is write-only and gated by 68S.

  • ob1, a GenDev forum member, tested this on real hardware and reported it in the thread "DREQ_FIFO Register" (2022). A 68000 read of $A15112 returns 0, and words written while 68S = 0 never reach the SH-2 sideHW[S112-wo][S112-68s][S001-r5112].
  • The jgenesis emulator reproduces this; see the emulator test below.
  • What to do: set 68S to 1 before writing to the FIFO.

FM changes hands by force, in both directions.

  • A 1 written to FM from the SH-2 takes VDP access even while the 68000 is using itDOC[S001-m-force].
  • A 68000 write to FM while the SH-2 uses the VDP gives access to the 68000DOC[S001-3.2fm].
  • Sega's Mars Check FM test writes FM from each CPU and expects the other to see the changeCODE[S189-fm][S189-fm68][S189-fmsh].
  • The test never writes FM while the other side is using the VDP, so it does not cover a take-over during an accessCODE[S189-fmlim].
  • What to do: agree on an owner through a communication word before changing FM.

Masking CMD drops its pending interrupt for now, not for good.

  • If VRES, V, H or PWM is masked before it is taken, it stays pending until clearedDOC[S001-cmd-others].
  • CMD is negated instead. It asserts again when CMD is re-enabled, if it was not clearedDOC[S001-cmd-neg][S005-cmd-save].

HEN is one bit for both SH-2sDOC[S001-hen-common]. Setting it from one processor changes the behaviour of the other.

Applications must not touch the standby changerDOC[S001-r4002b].

  • Sega's own Mars Check program reads it (a word read of $20004002) in its NMI and user-break handler, which is a counter-exampleCODE[S211-nmi].
  • The handler then only writes an error code to a communication port and hangs.

Clearing ADEN on a running 32X is outside Sega's rules. The initial program sets ADEN, and Sega allows no change after thatDOC[S001-a-aden].

  • Chilly Willy's menu for the Neo Myth flash cartridge clears it anyway, to get back from a 32X game on a Mega Drive reset. He describes this in the GenDev forum thread "32X register area" (2010)CODE[S162-myth].
  • The menu's reset code turns the 32X picture off and then writes 0 to the adapter control register, with the comment "disable and reset 32X"CODE[S162-myth2].
  • In the same thread another forum member, TmEE, reports that he never got the Mega Drive's own ROM mapping back after turning a running 32X offCOMM[S162-tmee].

Pulse width registers read back undefined data in bits 11 to 0DOC[S001-p-und].

  • Every pulse-width read in Sega's Mars Check program, on both SH-2 and 68000, tests only bit 15 or bit 14CODE[S189-pw][S189-pwsh][S189-pw68]. Sega's own code follows the rule, and nobody has published what the low bits actually returnCODE[S189-prac].

A write to a full PWM FIFO drops the oldest entryDOC[S001-p-old].

  • d32xr is the GitHub source of Doom 32X Resurrection, a homebrew rework of Doom for the 32X. Its PWM start-up code waits while the mono pulse-width register reads FULL (bit 15) before it writes each sample, so it never writes into a full FIFOCODE[S171-pwfull].

Tested on the jgenesis emulator#

On the jgenesis emulator, a test ROM writes $1234 to the FIFO with 68S = 0 and reads it back. Nobody has confirmed the results on a real 32X yet.

  • The 68000 read of $A15112 returns $0000EMU:jgenesis core 0.14.1[T025-68k].
  • The SH-2 also reads $0000 at $20004012, which is what the hardware report describes for a real consoleEMU:jgenesis core 0.14.1[T025-68k][T025-res].

Open questions#

  • Do bits 15 and 14 of the SH-2 DREQ control register follow the frame buffer write FIFO on a console, as Sega's equate names suggest? Nobody has published a test.
  • What exactly does "automatically cleared if SH2 does not interrupt clear" mean for INTS and INTM?
  • Does real hardware keep a masked CMD interrupt pending as the manual describes?
  • What do bits 11 to 0 of a pulse-width register return on a read, and does a write to a full PWM FIFO really drop the oldest entry?
  • Does setting HEN from one SH-2 change H interrupts on the other, as the shared bit implies?
  • What happens when an SH-2 accesses the video side while FM = 0? This is discussed on Memory map.
  • Whether an interrupt that is not cleared repeats or never fires again is the disagreement described under the interrupt clear registers above; see where sources disagree.
