Interrupts

This page describes the five interrupts that reach the two SH-2 processors, how to mask, clear and prioritise them, and a hardware limitation that Sega worked around with a fixed handler layout. Read it before you write an interrupt handler for either SH-2, or for the 68000 side of the 32X.

Summary#

  • Five interrupts per SH-2. They arrive on the IRL lines (interrupt request level inputs) at fixed priority levels: VRES 14, V 12, H 10, CMD 8, PWM 6DOC[S001-lvl][S005-lvl].
  • Masks are per CPU for V, H, CMD and PWM. HEN, the bit that allows H interrupts during vertical blank, is a single bit shared by both SH-2sDOC[S001-sep][S001-hen].
  • Clearing. Every interrupt is cleared by writing its own clear registerDOC[S001-clrby].
  • No SH-2 to 68000 interrupt existsDOC[S001-noint].
  • Sega's fixed set-up. All interrupts enter one shared handler that branches on the SR (status register) mask level. The FRT (free-running timer) is programmed to fixed values, and the odd priority levels are never usedDOC[S001-r1][S001-r2][S001-r3].
  • Disputed. Two members of the GenDev forum, a forum for hobbyist Mega Drive and 32X programmers, doubt that the FRT part of the set-up is needed on retail hardware. They are Chilly Willy, who wrote the Wolf32X port, and Snake; see the section on disagreements.

Details#

Sources, levels, masks#

Each interrupt has a cause, a priority level, a mask bit in the interrupt mask register at $20004000 and a write-only clear register. VRES has no mask bit.

InterruptCauseSH-2 IRL levelMask bit ($20004000)Clear register (SH-2)Source
VRESMega Drive reset button14none$20004014DOC[S001-l14][S001-c14]
Vvertical blank12V (bit 3)$20004016DOC[S001-l12][S001-c16]
Hhorizontal blank10H (bit 2)$20004018DOC[S001-l10][S001-c18]
CMDthe 68000 writes INTM or INTS in $A151028CMD (bit 1)$2000401ADOC[S001-l8][S001-c1a][S001-r5102]
PWMPWM cycle timer6PWM (bit 0)$2000401CDOC[S001-l6][S001-c1c]

The priority order is VRES, then V, H, CMD and PWM. All five are taken as SH-2 IRL auto-vector interruptsDOC[S001-prio]. Bit layouts are on System registers.

Clearing#

  • An interrupt stays asserted until its clear register is writtenDOC[S001-clrby].
  • The clear register pages also say that an interrupt that is not cleared "will no longer occur"DOC[S001-noocc]. The two statements disagree; see where sources disagree.
  • After the write that clears an external interrupt, leave two or more cycles before RTE (return from exception), and execute two or more instructions after itDOC[S001-rte].

Masking CMD differs from the others#

  • If an interrupt is masked before it is taken, VRES, V, H and PWM stay pending until clearedDOC[S001-pend].
  • CMD is negated instead. It asserts again when CMD is unmasked, because it stays latched until clearedDOC[S001-cmdneg][S005-cmdsave].

H interrupt timing#

  • The H count register sets the interval in lines. 0 means every lineDOC[S001-hc].
  • A new value is loaded into the internal counter only when H blank ends. A write outside H blank can therefore give one more interrupt at the old intervalDOC[S001-hclate].
  • HEN is shared by both SH-2s and changes the H interrupt interval as wellDOC[S001-hen].

Sega's interrupt rules for the 32X#

Sega's manual sets five rules for programs that use two or more of these interrupts together with the SH-2's on-chip peripheral interruptsDOC[S001-rintro][S005-rules]. The FRT is the SH-2's free-running timer; TIER, OCRA, FTCSR and TOCR are its registers.

RuleWhat to doSource
1Keep the SR interrupt mask at 1 or more. Never use levels 15, 13, 11, 9, 7 or 1.DOC[S001-r1]
2Do not use the FRT in programs. Set TIER = $01, OCRA = $0002, FTCSR = $01, TOCR = $E2.DOC[S001-r2][S001-r2v]
3Point every interrupt vector except NMI and user break to one routine, which branches on the SR level.DOC[S001-r3]
4Return at once from interrupts at levels 15, 13, 11, 9, 7 and 1.DOC[S001-r4]
5Leave two or more cycles between the clear-register write and RTE.DOC[S001-rte]
  • Bulletin. Sega's 32X Technical Bulletins are numbered notes from Sega's Developer Technical Support, issued to 32X developers in 1994. Bulletin 10 (September 1994) adds that the FRT must be initialised even when no interrupt is usedDOC[S070-b10].
  • Homebrew. Some homebrew departs from the fixed FRT values. d32xr reprograms the master SH-2's FRT to count at SYSCLK/128 with its overflow interrupt on, for profilingCODE[S032-tcr]. It notes that this does not work in the Fusion emulatorCODE[S032-note].
  • Registers. The FRT registers are described on SH-2 on-chip peripherals on the 32X.

The SH-2 interrupt limitation (Supplement 2)#

Sega's Hardware Manual Supplement 2, on pages 8 and 9, states the underlying problem and the fix.

ItemWhat Supplement 2 saysSource
Limitation 1An external interrupt (VRES, V, H, CMD or PWM) that arrives during the acknowledge period of another interrupt, or of a lower-level external one, is not recognised.DOC[SP2-l1]
Limitation 2With several interrupts pending, the SH-2 may branch to a different vector than the one it took. The SR mask level is still right.DOC[SP2-l2][SP2-l2b]
Fix 1Drive the SH-2 FRT output from software inside each external interrupt routine, taking the pipeline into account so one interrupt is not handled twice.DOC[SP2-f1]
Fix 2Send every interrupt, internal and external, to one address and branch on the SR value.DOC[SP2-f2]
Precaution aKeep the SR mask at level 1. Normal operation fails at 0.DOC[SP2-pa]
Precaution bSH-2 on-chip peripheral interrupts should use levels 2 to 5.DOC[SP2-pb]
Precaution cThe EVA chip cut 2.5 has the problem corrected, but the first production units use an unmodified chip, so the fix is required.DOC[SP2-pc][SP2-pc2]

Clearing an interrupt takes three further precautions:

  • The write to the clear register goes through the SH-2 write buffer, so the next instruction runs before the write lands. Read back from the same address to synchroniseDOC[SP2-wb].
  • After that read, RTE needs a 1-cycle gapDOC[SP2-rte].
  • Re-enabling interrupts with LDC to SR needs at least 4 cycles after itDOC[SP2-ldc].

Sega's correction sample, step by step#

Supplement 2 ends with an "Interrupt Correction Sample Program" dated July 6, 1994, on its last four pages. Knuckles' Chaotix, Sega's Mars Check and d32xr all follow its shape (see "What shipped code does" below). The listing is a shortened version of Sega's sample, with comments added. Sega's "push 0,1" macro is written out as two stores.

; every IRL vector (levels 1 to 15) points at m_int
m_int:  mov.l   r0,@-r15        ; the handler runs inside someone
        mov.l   r1,@-r15        ; else's code: save what it uses
        sts.l   pr,@-r15        ; save the return address
        stc     sr,r0           ; SR bits 7-4 = current mask level
        shlr2   r0              ; level x 4 = offset into a long table
        and     #$3C,r0
        mov.l   #inttable,r1
        add     r1,r0
        mov.l   @r0,r1          ; handler for this level
        jsr     @r1
        nop
        lds.l   @r15+,pr
        mov.l   @r15+,r1
        mov.l   @r15+,r0
        rte
        nop

vint:   stc.l   gbr,@-r15
        mov.l   #$20004000,r0   ; SH-2 system registers via GBR
        ldc     r0,gbr
        mov     #$F0,r0         ; mask level 15: nothing can nest
        ldc     r0,sr
        mov.l   #$FFFFFE10,r1   ; FRT register block
        mov.b   @(7,r1),r0      ; TOCR
        xor     #2,r0           ; flip the FRT output level (bit 1)
        mov.b   r0,@(7,r1)
        mov.w   r0,@($16,gbr)   ; V interrupt clear
        ; ... at least 5 clocks of other work before returning
        ldc.l   @r15+,gbr
        rts                     ; back into m_int, which does the RTE
        nop

The dispatcher works because the SH-2 raises the SR mask to the level of the interrupt it takes, so the mask level names the source. The handler then does three things in a fixed order. It masks everything, then it flips the FRT output level (the "bump" that stops the same interrupt from being taken twice). Only then does it clear the interrupt.

  • One table for all levels. The table gives odd and even levels of each external interrupt the same handler, and levels 1 to 5 point at a routine that returns at onceDOC[SP2-same].
  • The same body for every source. The supplement's comment says the V handler pattern is to be repeated for H, CMD and PWMDOC[SP2-hcmd].
  • Time before the return. The sample leaves "5 clocks or more" of other work between the clear-register write and the return, instead of reading the clear register backDOC[SP2-5clk].
  • Start-up. Before it enables interrupts the sample programs the FRT, waits for comm0 to read 0 (the 68000's go signal), and then lowers the SR mask to level 2DOC[SP2-start].

Why: the double-acknowledge problem#

Technical Bulletin 27 (December 1994) explains the cause. With two or more interrupt types in use, one interrupt can be acknowledged twiceDOC[S070-b27a]. Sega's example runs like this:

  • A CMD interrupt is taken at level 8DOC[S070-b27b].
  • A V interrupt arrives before SR is masked and is served firstDOC[S070-b27b].
  • The FRT output changes the external level, and the SH-2 takes the CMD interrupt again as level 9, and later once more as level 8DOC[S070-b27b].

Sega says this happens on the 32X only, not on the SaturnDOC[S070-b27sat]. Its fix is the handler code in Hardware Manual Supplement 2DOC[S070-b27fix].

The 32XDK wiki (the community-written wiki for 32X developers on GitHub) gives a different account, quoting Toshiyasu Morita's "Programming the 32x FAQ":

  • Early 32X units use the 2.5 cut of the SH-2, which can jump to a low-priority vector and lose a higher one arriving within a 3-cycle windowCOMM[S009-cut]. Supplement 2 says the reverse about cut 2.5; see where sources disagree.
  • The FRT output drives the lowest IRL bit, so it keeps re-triggering pending interruptsCOMM[S009-frt].
  • SR must be set to 2, not 0, to mask interruptsCOMM[S009-sr2].
  • The same page reads the schematics as FTOA (the FRT output) wired to /IRL0 on both CPUsCOMM[S009-sch].

What shipped code does#

Knuckles' Chaotix has SH-2 code that follows Sega's rules. SoullessSentinel posted a disassembly of it in the GenDev forum thread "68K to SH2 DMA FIFO" (2013).

  • One IRQ entry reads SR and branches through a tableCODE[S020-sr][S020-src].
  • The Chaotix CMD handler first toggles a bit in the FRT's register block at $FFFFFE10 (offset 7, XOR 2)CODE[S020-frt][S020-frt2].
  • It then writes the CMD clear registerCODE[S020-clr].
  • In the same thread, another forum member, TapamN, identifies that write as toggling the timer A compare output levelCOMM[S020-tocr].

Sega's own Mars Check test program does the same in its SH-2 code.

  • Start-up. It sets up the FRTCODE[S187-frt].
  • Entry. Every IRL vector on both CPUs enters one unified handler, which branches through a table on the SR maskCODE[S187-uni].
  • Each V, H, CMD and PWM handler first masks all levelsCODE[S187-f0]. It then reads TOCR, flips bit 1 and writes it backCODE[S187-bump][S187-bumpc]. Then it writes its clear register. This flip is the "bump" of the FRT output.
  • VRES is the one IRL handler without the bumpCODE[S187-all].
  • No read-back. None of the handlers reads its clear register back before RTECODE[S187-norb]. The CMD handler's next read is communication port 0, not the clear registerCODE[S187-cmdrd].
  • What that means. Mars Check skips Supplement 2's read-back rule, as Supplement 2's own sample program does; both rely on enough work between the clear and the return insteadCODE[S187-prac]DOC[SP2-5clk].
  • Mask level. The program runs with the SR mask at 1CODE[S187-sr][S187-src].

On a VRES, Sega's Mars Check handler builds its own return frame into its start-up code, with SR = $F0CODE[S211-vres2].

  • On the way it clears the SH-2 DMAC (see DMA (68000 to SH-2 FIFO, SH-2 DMAC)). It does not read RV or touch the watchdogCODE[S211-norv].
  • Homebrew start-up code does the same job. The start-up file sh2_crt0.s of the Yeti3D homebrew, as the forum member ob1 quotes it in the GenDev thread "Reset and VRES" (2021)CODE[S113-src], clears the VRES interruptCODE[S113-clr] and masks all interrupt levelsCODE[S113-mask].
  • Then it waits for the slave and copies the ROM data to SDRAM again before it restartsCODE[S113-reset].

68000 side#

  • All 68000 interrupts must be disabled while RV = 1, says Technical Bulletin 9 (September 1994)DOC[S070-b09].
  • The 32XDK wiki gives a rule of thumb: every interrupt handler, on both SH-2s and the 68000, runs from RAMCOMM[S009-ram].

Pitfalls#

All 32X quirks are collected on Bugs and quirks.

An interrupt can be taken twice. Sega's unified handler with the FRT set-up is the documented fixDOC[S070-b27a].

  • Shipped Chaotix uses itCODE[S020-frt2].
  • d32xr, the GitHub source of Doom 32X Resurrection, sets the FRT up with OCRA = 1 and flips TOCR at the top of its interrupt handlersCODE[S184-ocra][S184-tocr1][S184-tocr0].

Never unmask to 0 on the 32X. The FRT-driven IRL bit then interrupts continuously, according to the 32XDK wikiCOMM[S009-sr2].

  • Sega's Mars Check program runs with the mask at 1CODE[S187-sr], and Supplement 2's sample enables interrupts at mask level 2DOC[SP2-start].

A high-level interrupt can overtake a low one that arrived first. Take care with an H interrupt right before a V or PWM interruptDOC[S001-order].

The first production 32X SH-2s need the fix (Supplement 2, precaution c)DOC[SP2-pc2].

  • Sega's Mars Check program applies the FRT bump in every V, H, CMD and PWM handlerCODE[S187-all]. Which retail units carry the unmodified chip is not documented.

A clear-register write must be read back before RTE, because of the write bufferDOC[SP2-wb].

  • Sega's own Mars Check handlers do not read back (see "What shipped code does" above).
  • Shipped games do. After Burner writes the VRES clear register through GBR and reads it back on the next instructionCODE[S233-ab]. A Golf Magazine routine does the sameCODE[S233-golf].
  • Of 39 32X ROMs (retail games, prototypes, a demo cart and Sega's sample and test programs), 22 contain this write-then-read pattern, at 150 places in allCODE[S233-total]. Some of those places may be unrelated reads, so 150 is an upper bound.

Forum dispute on the FRT workaround.

  • The GenDev forum thread "DMA to PWM" (2010) is about playing PWM sound by DMA. In it, Chilly Willy says he left the FRT set-up out of his Wolf32X port and nobody has complained. He reads Sega's bulletins as meant for the developer cards, not the release hardwareCOMM[S048-cw].
  • Snake, another forum member, replies in the same thread that it was a workaround for a reset-button lock-up and does not helpCOMM[S048-snake].
  • Sega's rule 2 takes the other side: programs may not use the FRT, and they must start it with fixed valuesDOC[S001-r2].
  • Chilly Willy returns to the bug in the GenDev forum thread "simplest method for 32x sound?".
    • In 2025 he describes the bug as lost nested interrupts on some SH-2 chips shipped in 32X units, fixed by the FRT bump in a unified handler.
    • Chilly Willy says his old code lacks it; in 2022 he points to d32xr as having itCOMM[S186-bug][S186-old][S186-d32xr].
  • Sega's own Mars Check program has the unified handler and the bumpCODE[S187-uni][S187-all].

A masked CMD interrupt is deferred, not lostDOC[S005-cmdsave].

68000 interrupts must be off while RV = 1DOC[S070-b09].

  • d32xr's 68000 code masks interrupts (#$2700) before it sets RV and unmasks after it clears RVCODE[S088-rvints][S088-rvints2].
  • Chilly Willy's working save-RAM read routine, posted in the GenDev thread "Accessing SRAM" (2009), begins with move.w #0x2700,sr, commented "disable ints"CODE[S182-fix][S182-ints].

  • Interrupt-driven PWM and DMA are on the audio pages, for example DMA-driven PWM.
  • Dual-CPU patterns are on Dual-CPU synchronisation on the 32X.

Where sources disagree#

  • Is the FRT set-up needed on retail hardware? Sega's rule 2 and bulletin 27 say yes. In the GenDev thread "DMA to PWM" (2010), Chilly Willy and Snake argue against it. Chilly Willy left it out of Wolf32X with no complaints, and Snake calls it a reset-button workaround that does not help.
  • Which SH-2 cut carries the interrupt bug? The 32XDK wiki says the 2.5 cut has it. Supplement 2 says the opposite: cut 2.5 has the problem corrected, and the first production units use an unmodified chip that still has it.
  • Which FRT start values? The manual's rule 2 sets TIER to 1 and OCRA to 2DOC[S001-r2v].
    • Supplement 2's own sample program (July 6, 1994) leaves TIER at 0 and sets OCRA to 1DOC[SP2-start].
    • Sega's Mars Check program uses the sample's valuesCODE[S187-frt], and d32xr also uses OCRA = 1 (see the pitfalls above).
    • All of them set TOCR to the same value, and all flip it in the handlers, which is the part of the fix that matters.
  • What happens to an uncleared interrupt? One manual page says it stays asserted until cleared, another says it will no longer occur. See System registers.

Open questions#

  • Which retail 32X units carry the unmodified SH-2 that needs the fix, and does a unit with the corrected chip still need the FRT bump?
