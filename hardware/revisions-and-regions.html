Revisions and regions

The 32X was built in several hardware revisions, from early Sega development targets to the production units that shipped, and it came in NTSC and PAL versions. This page lists what differs between them and what you must do in software to cope. Read it when your code behaves differently on a development board, a PAL console or an early production unit.

Summary#

  • Region changes every clock. NTSC and PAL 32X units run from different master clocksDOC[S001-fosc]. See Timings and clocks.
  • Development targets differ from each other. Sega's targets Ver. 1.0 and 1.1 behaved differently from Ver. 2.0 in DMA length, PWM reads, the CD-ROM interface, region and picture alignmentDOC[S002-dma][S002-pwm][S002-cd][S002-jp][S002-dot1].
  • Production units use 2 Mbit of SDRAMDOC[S002-sdram].
  • The first production units use an SH-2 without Sega's interrupt fix, so the software workaround is required. Sega's Hardware Manual Supplement 2 (July 1994), a correction sheet to the 32X Hardware Manual, says soDOC[SP2-pc2]. See Interrupts.
  • PWM channels. In the GenDev forum thread "DMA to PWM" (July 2010), the member Chilly Willy saw PWM left and right swapped on one set-upCOMM[S048-swap]. In the same thread the member TmEE replies that VA0 and VA1 Model 2 and all Model 1 Mega Drives wire the 32X audio the right wayCOMM[S048-tmee].

Details#

Development targets (April and May 1994)#

Sega's "32X Hardware Information" notes compare its development boards in their part 2. "Target Ver. 1.x" covers the early boards, "Ver. 2.0" the later ones. The differences are:

  • FIFO DMA length. On Ver. 1.x a 68000-to-SH-2 FIFO DMA must stay under $100 words per transferDOC[S002-dma]. Ver. 2.0 has no such limitDOC[S002-dma2].
  • PWM reads. Ver. 1.0 cannot read the PWM registers from the 68000; Ver. 2.0 canDOC[S002-pwm].
  • CD-ROM interface. Ver. 1.0 cannot use it; Ver. 2.0 canDOC[S002-cd].
  • Region. Ver. 1.x allows no region other than "JAPAN"DOC[S002-jp].
  • Dot offset against the Mega Drive picture. On Ver. 1.0 the 32X picture sits 2/3 dot to the leftDOC[S002-dot1]. On Ver. 2.0 it is off by 1/2 dot left or rightDOC[S002-dot2]. On production units it lies between 1/2 dot left and 1/2 dot right, depending on the Mega DriveDOC[S002-dot3].
  • Brightness against the Mega Drive picture. Ver. 1.0 is slightly different; Ver. 2.0 is identicalDOC[S002-bright].
  • SDRAM. The Ver. 1.0 boot ROM is set for 4 Mbit. Ver. 2.0 has 4 Mbit parts set as 2 Mbit, and production units use 2 MbitDOC[S002-sdram0][S002-sdram].

On Ver. 1.x the picture outline could be unstable from colour variation at the edges of drawn dataDOC[S002-contour]. Target SH-2 access times per version are on Memory map.

Interface chip versions#

The interface chip connects the 32X to the Mega Drive. Sega's 32X Technical Bulletin 11 (September 1994) names three versions. The Technical Bulletins are numbered notes that Sega's Developer Technical Support sent to Sega and third-party developers in 1994.

Both the 5818 and the 5818A ship in productsDOC[S091-mixed]. Sega asked for final checks on a 5818A unit, because with the 5818 SH-2 and 68000 communication errors "seldom occur"DOC[S091-err].

Development targets against production#

Further Technical Bulletins from 1994 say how the development targets differ from the production units.

  • SH-2 cut on the targets. Bulletin 5 says target Ver. 2.0 does not operate unless the SH-2 is cut 2.3 or laterDOC[S144-cut]. For the first production chips, see Supplement 2 on Interrupts.
  • SH-2 in production, from memory. TMorita, a GenDev forum member, recalls in the thread "32X overclocking" (2008) the 32X shipping with the FC3 version of the SH-2 and the Saturn with FC4COMM[S173-fc3].
    • TMorita describes FC3 as an older tape-out, not reliable at 28 MHz and with interrupt bugs, and says he writes "from memory"COMM[S173-fc3][S173-mem].
  • Z80 writes lock the 68000. Bulletin 15 says Z80 writes to $840000-$9FFFFF and $A15100-$A153FF lock the 68000 from target 2.0B/2.1 onDOC[S148-z80][S148-lock].
    • Z80 reads there are fine, and so are Z80 writes to Mega Drive work RAM and the PSGDOC[S148-ok].
    • The bulletin says production units ("their products") have the same limitationDOC[S148-prod].
    • The 32XDK wiki prints the range as $84000 and calls the bug "supposedly fixed"COMM[S009-z15].
  • SDRAM. Bulletin 26 says the development boards carry 4 Mbit, of which the boot ROM enables 2 Mbit. Production units carry 2 MbitDOC[S156-2mb][S156-lim].
  • NMI. Bulletin 16 says target 2.1 wires the NMI of each CPU to one pointDOC[S149-nmi].
  • Video encoder and filter. Bulletin 21 says target 3.0, WS and production units use a different encoder and filter from target 2.0xDOC[S152-enc]. Colours are more vivid and there is less blur, so do final graphics checks on these unitsDOC[S152-diff].
  • Cartridge access at power-on. Bulletin 17 says the development board boots from a 68000-side boot ROM. Write byte 1 to $A14100 to release itDOC[S150-a14100].
  • SYSREG access after certain SDRAM writes. Bulletin 31 says such an access crashes the SH-2, and that production units have this correctedDOC[S095-crash][S095-fixed].
  • VRES reset with RV = 1. Bulletin 6 says this is fixed from target 2.1DOC[S090-v21].

Boot ROMs#

Sega Retro, a community wiki about Sega hardware and games, lists three 32X (US) boot ROM dumps: 68000, SH-2 master and SH-2 slaveCOMM[S013-bios]. The two SH-2 boot ROMs differ in content, per SegaDOC[S001-bootdiff].

Techniques#

  • Offer a left/right swap option in PWM audio code. In the "DMA to PWM" thread Chilly Willy wrote that his final code would have a setting to swap the channelsCOMM[S048-opt].
  • Check the Mega Drive region in code, as shipped games do.
    • BC Racers reads the version register $A10001, shifts it right by 6, masks 3 and compares the result with 0 and 1CODE[S234-bc].
    • Of 39 32X ROMs (retail games, prototypes, a demo cart and Sega's sample and test programs), 31 contain such reads of $A10001. Some hits may be the constant sitting in data, so 31 is an upper boundCODE[S234-tot]. More on Shipped-code survey: what 32X ROMs do with the registers.

Pitfalls#

Picture alignment against the Mega Drive varies by console. It is up to half a dot either way on production unitsDOC[S002-dot3].

First production SH-2s need the interrupt workaroundDOC[SP2-pc2].

  • d32xr, the GitHub source of Doom 32X Resurrection (a homebrew rework of Doom for the 32X), implements it. Its FRT (free-running timer) is set up with OCRA = 1CODE[S184-ocra].
  • d32xr's common interrupt entry writes TOCR for output 0CODE[S184-tocr0].
  • Each of its V, H, CMD and PWM handlers writes TOCR back to output 1 and reads itCODE[S184-tocrv][S184-tocrp].

TOCR sets the level of the FRT output pin. Flipping it to 0 on entry and back to 1 in each handler is the "bump" of Sega's workaround, which keeps the same interrupt from being taken twice. Interrupts explains it and which SH-2 chips carry the bug.

PWM left and right can come out swapped on some console and cable combinationsCOMM[S048-swap].

  • Chilly Willy heard the channels reversed on one console through a standard stereo composite cable. The same code on his CDX with a 32X played them the right way roundCOMM[S048-swap][S048-cdx].
  • Chilly Willy asked whether the cable or the Model 2 against the CDX was the causeCOMM[S048-why].
  • TmEE replied that VA0 and VA1 Model 2 units and all Model 1 units connect the 32X signals the right wayCOMM[S048-tmee].
  • Nobody has published a cause.
