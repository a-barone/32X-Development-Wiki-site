Memory map

This page says where each part of the 32X appears in the address space of the 68000 and of the two SH-2 processors. You need it to know which address reaches the frame buffer, the palette, the registers or the cartridge ROM from each CPU. It also explains which of two address views to use on the SH-2, and which two control bits (FM and RV) decide who may touch what.

Summary#

  • The 68000 sees the 32X only after it is switched on. Sega's initial program in the cartridge must first set the ADEN bit (32X enable) to 1DOC[S001-3.1a].
  • With ADEN = 1 the 68000 finds the frame buffer at $840000, cartridge ROM at $880000 and $900000, and the 32X registers from $A15100DOC[S001-3.1map][S001-3.1m88][S001-3.1m90][S001-3.1msys].
  • Both SH-2s see one identical mapDOC[S001-3.1sh].
  • Every SH-2 region has two addresses. One is cached ($0xxxxxxx) and one is cache-through ($2xxxxxxx)DOC[S001-3.1sh-boot]. Registers must be accessed through the cache-through addressDOC[S001-3.4ct].
  • Two bits arbitrate access. FM gives the video side (frame buffer, overwrite image, VDP registers, palette) to one CPU at a time. RV takes the cartridge ROM away from the SH-2sDOC[S001-3.1fmsh][S001-3.1rvsh].
  • Neither CPU sees the other's private hardware. The 68000 cannot reach SDRAM, and the SH-2s cannot reach Mega Drive hardwareDOC[S001-2.1][S001-2.2md].

The parts behind these addresses are described on 32X hardware overview.

Details#

How to read the tables#

  • Every address names its CPU side. The two sides are never mixed in one column.
  • Every SH-2 address names its view. A cached access goes through the SH-2's cache. A cache-through access bypasses it and always reaches the real device.
  • Addresses are hex with a $ prefix. The Sega manuals write them as 84 0000h or 2000 4000h.
  • A row's address is where the region starts. Each region runs up to the start of the next row, as in Sega's own tables.

The interrupt vectors work differently from a plain Mega Drive, because the first 256 bytes of the address space belong to a vector ROM inside the 32X:

  • Vector ROM contents. It holds $00000000 at vector offset $00, and $880200, $880206, $88020C at offsets $04, $08, $0C, continuing to offset $FCDOC[S005-p15vec]DOC[S005-p15vec2].
  • Jump table. The cartridge supplies a table of 6-byte JUMP instructions starting at $880200 (cartridge offset $200)DOC[S001-3.1jt]DOC[S005-p16jt].
  • Where a vector lands. The vector at offset 4N lands on $880200 + 6(N-1)DERIVED[S005-p15vec]. For example, the H interrupt vector ($70) goes to $8802A2 and the V interrupt vector ($78) to $8802AEDERIVED[S005-p15vec].
  • Second opinion. "Dr. DevSter's Guide to The Sega 32x", a text file by Joseph Norman on his devster.monkeeh.com website, lists the same two jump addressesCOMM[S023-h][S023-v].
  • Cost. Each 68000 interrupt passes through at least one extra jump, which adds a few cycles to its responseCOMM[S165-ind][S165-cyc].
  • More. The boot sequence and the cartridge header are on Boot, security and ROM headers.

Access rules: FM and RV#

Two control bits decide which CPU may use shared hardware. FM is the VDP access bit: it says whether the Mega Drive side (0) or the SH-2 side (1) owns the frame buffer, overwrite image, VDP registers and palette. RV is the ROM-to-VRAM bit: it says whether the 68000 side (1) has taken the cartridge ROM away from the SH-2s.

BitValue68000 sideSH-2 sideSource
FM0may access frame buffer, overwrite image, VDP registers, palettereads undefined, writes ignored (section 3.1; see the note below)DOC[S001-3.1fm][S001-3.1fmsh0]
FM1reads undefined, writes ignoredmay access themDOC[S001-3.1fm1][S001-3.1fmsh]
RV0cartridge ROM at $880000-$9FFFFFmay read cartridge ROMDOC[S001-3.1rv0][S001-3.1rvsh]
RV1cartridge ROM at $000100-$3FFFFFcartridge access waits until the 68000 clears RVDOC[S001-3.1rv1][S001-3.1rvsh]
  • FM = 0 on the SH-2 side. The manual contradicts itself on whether an SH-2 write is ignored or held. Section 3.1 says it is ignored, while section 3.4 says the SH-2 access waits until FM = 1DOC[S001-3.4wait]. See where sources disagree.
    • Tested on the jgenesis emulator, a write is not held until FM = 1 and does not land; see the emulator test below.
  • Where the bits live. FM is bit 15 of the SH-2 interrupt mask registerDOC[S001-3.4fm]. The SH-2 can only read RVDOC[S001-3.1rvro].

Simultaneous access#

When the 68000 and an SH-2 access the same area at once, the SH-2 winsDOC[S001-3.1pri]. Otherwise access is first come, first served: the second access waits until the first endsDOC[S005-p16fcfs]. Arbitration in full is on Bus arbitration.

Access cost per region (wait states)#

A wait state is one extra bus clock that a CPU spends waiting for a slow device. A 68000 bus cycle is at least 4 clocks and an SH-2 bus cycle at least 2 clocksDOC[S001-4.1bus]. Each wait adds 1 clock to that minimumDOC[S001-4.1wait]. Clocks, line and frame timing are on Timings and clocks.

Section 1.12 of Sega's R4 manual, pages 77 and 78, gives the access timings in the table belowDOC[S005-p77rom].

  • A palette collision costs a line. A wait of 64 us is one display line: the CPU waits a whole line when its palette access collides with the VDPDOC[S001-4.1line].
  • The frame buffer write FIFO holds 4 words. An SH-2 write costs 3 clocks while the FIFO has room and 5 clocks when it is fullDOC[S001-4.1fifo].
  • Idle cycles do not buy a faster write. The frame buffer write figures assume back-to-back writes. An idle cycle between two writes shortens the next one by the idle time, but never below 3 clocksDOC[S005-p77idle].

Techniques#

Copy data that an SH-2 reads often from cartridge ROM into SDRAM first. The manual says this restores the SH-2's speed and avoids competing with the 68000 for the ROMDOC[S001-3.4rom]. More techniques are listed on Optimization techniques.

Pitfalls#

All 32X quirks are collected on Bugs and quirks.

The SH-2s cannot write to the cartridge. There is no strobe and no bus cycle, so have the 68000 do cartridge writesHW[S178-none].

Save RAM writes need RV = 1. With RV = 0 the LWR# strobe never assertsHW[S178-lwr]. Sega's Technical Bulletin 7 (September 1994) disagrees; see Cartridge bank switching.

Save RAM needs odd bytes.

  • Chilly Willy's save-RAM code, posted in the GenDev thread "Accessing SRAM" (2009), worked on emulators but failed on a real 32X (MD-Pro cart). It worked once he switched from even to odd bytesHW[S182-odd][S182-oddok].
  • His working code sets RV = 1 and $A130F1 before the access and clears RV afterCODE[S182-fix][S182-rv].
  • TmEE, a GenDev forum member, adds in the same thread that Mega Drive carts with save RAM never had it on even addressesCOMM[S182-tmee].

With a Sega CD, never write CD program RAM while RV = 1. The 68000 locks until power-off, Chilly Willy reports from real hardware in "Limitations in current 32X emulators"HW[S169-lock].

The H-interrupt vector is writable even with ADEN = 1. The rest of the vector area is internal ROM, but the H-interrupt vector can be written. ob1, a GenDev forum member, reports this in a 2021 post to the thread "32x 'security code' reverse engineered". He wrote there and tested it on the Kega Fusion emulator and on real (PAL) hardwareHW[S116-w][S116-hw].

  • ob1 points out that Sega's initial program writes $8802A2 thereCOMM[S116-ip][S116-h].
  • srg320, another member of the forum, replies in the same thread that it may be a separate register, as on the Sega CDCOMM[S116-reg].
  • The jgenesis emulator behaves the same; see the emulator test below.

A cache-through read of SDRAM still bursts 8 words. A single-word read costs the full 8-word burstDOC[S001-4.1burst]. SDRAM reads are 8-word bursts and writes are single wordsDOC[S005-p78burst]. To read several neighbouring words, read them together.

Byte writes of 0 to the frame buffer are ignored. This holds from the 68000 and from the SH-2. A 0 word write worksDOC[S001-3.6fb][S002-1zero].

  • Sega's Mars Check hardware test program checks the overwrite area in its tests 89 and 90, on both frame buffers. TascoDLX, a GenDev forum member, lists them in the thread "Mars Check Program results for Kega Fusion v3.61" (2009)COMM[S115-ow].
  • TascoDLX relays that all Mars Check tests have been reported to pass on real hardwareCOMM[S115-hw]. dilworks, commenting on issue 96 of the PicoDrive emulator's GitHub repository (2019), reports that they passCOMM[S179-hw].
  • Mars Check's SH-2 byte-write test fills the frame buffer with $FF and writes the bytes 0 to $FF one at a time. It expects each byte where it wrote 0 to still hold $FFCODE[S188-bw][S188-bwc][S188-prac].
  • What to do: write a word, not a byte, when the value is 0.

Palette access must be by word. Byte access to the palette is not allowed on either sideDOC[S001-3.1pal][S001-3.1palsh].

  • Every palette access in Mars Check is a word or a longword, on the SH-2CODE[S188-palsh] and on the 68000CODE[S188-pal68]. Nobody has published what a byte access actually does.

Only the palette may use a cached address. The other VDP areas are cache-through onlyDOC[S001-3.3ct][S001-3.3pal].

  • Mars Check's SH-2 code reaches the registers, VDP, palette and frame buffer only through cache-through addressesCODE[S188-ct].

FM changes hands by force. A 68000 write to FM while an SH-2 is using the VDP switches access to the 68000DOC[S001-3.2fm].

  • With FM = 1 from the SH-2 side, a 68000 access is cut off and what follows is not guaranteedDOC[S001-3.4force].
  • Page 75 of Sega's R4 manual, on 68000 access, states the mirror case. When the 68000 sets FM to 0, an SH-2 access is cut off in the same wayDOC[S005-p75force].
  • Mars Check takes FM explicitly: before its palette fill the 68000 clears FM and repeats until it reads back clearCODE[S188-fm].

$A130F0 is not a bank set register.

  • Figure 3.1 of Sega's R4 manual marks $A130F0 "See MD Manual"DOC[S005-p15c].
  • The Mega Drive's own bank registers are at $A130F1-$A130FF, odd addressesDOC[S005-p16bank].
  • The 32X bank set register is $A15104DOC[S001-bk-reg].
  • notaz, the author of the PicoDrive emulator, ran a read test of the $A130xx page on hardware with a Sega CD attached. He posted it in the GenDev forum thread "32X register area" (2010).
    • The whole page reads open bus with the 32X on or off, except the "MARS" IDHW[S162-a130].

The end of the fixed ROM window is printed two ways. $07FFFF is the end that matches the stated 4 Mbit.

  • The sentence on page 16 of Sega's R4 manual says $000000-$7FFFFF "(4Mbit)"DOC[S005-p16fix]. The 32XDK copy of the manual has the same sentenceDOC[S001-3.1fix].
  • Figure 3.1 on page 15 says $0007FFFFDOC[S005-p15fix]. Sega's US hardware manual, page 16, says 07FFFFHDOC[S074-p16fix].
  • The "(4Mbit)" is the size of the $000000-$07FFFF range: 524,288 bytes x 8 = 4,194,304 bits = 4 MbitDERIVED[S005-p15fix][S005-p16fix].
  • The jgenesis emulator shows cartridge $000000-$07FFFF; see the emulator test below.

Tested on the jgenesis emulator#

jgenesis is a Mega Drive and 32X emulator whose source is on GitHub. These results come from its version 0.14.1. Nobody has confirmed them on a real 32X yet.

  • SH-2 write to the frame buffer while FM = 0.
    • The write is not held until FM = 1 and does not land. A stall shorter than the 68000's wait cannot be excluded. This is the behaviour the manual's section 3.1 describesEMU:jgenesis core 0.14.1[T001-x005c][T001-x005b].
  • The 68000 window $880000-$8FFFFF.
    • It shows cartridge $000000-$07FFFF, the reading given by Sega's figureEMU:jgenesis core 0.14.1[T024-x002][T024-ctl][T024-x002b].
    • With bank 0, $880000 and $900000 show the same data.
  • The 68000 vector at $70 with ADEN = 1.
    • It is writable: $00880806 read back after the write, while $78 still reads $008802AE from the vector ROMEMU:jgenesis core 0.14.1[T026-res].
    • The vector reads $008802A2 as the initial program left it, and a 68000 write of $00880806 sticksEMU:jgenesis core 0.14.1[T026-ip][T026-w].

Where sources disagree#

  • Fixed cartridge window end. The sentence on page 16 of Sega's R4 manual, and the 32XDK copy, say $7FFFFF. The R4 figure, Sega's US manual and section 3.5 say $07FFFF (see the pitfall above). Details: where sources disagree.
  • SH-2 access to the video side while FM = 0. One section of the manual says the access is ignored, another says it is held until FM = 1. The same disagreement exists for the frame buffer on Frame buffer and line table.
