Emulators and their 32X accuracy

An emulator is only useful for 32X work where it behaves like the hardware. This page takes the emulators that the sources test with 32X code one by one: Kega Fusion, Gens/GS, GensKMod, BlastEm, ares, jgenesis and PicoDrive. For each it says what it gets right, what it gets wrong, and what to use it for.

Summary#

  • For DMA PWM sound, Kega Fusion 3.64. Chilly Willy, who wrote the DMA PWM test ROMs these reports use, says his interrupt-driven DMA PWM works on a real 32XHW[S046-1] and on Fusion 3.64EMU[S046-2]. He wrote it in the Sonic Retro forum thread "Interrupt-Driven DMA PWM on the 32X" (2012).
  • For checking the hardware rules, jgenesis. It runs all 161 tests of Sega's Mars Check test program with no error (see the emulator section)EMU:jgenesis core 0.14.1[T028-1].
  • For timing, neither of the two. bakemono finds that Fusion "does not emulate all of this timing nuance"EMU[S025-1]. jgenesis does not slow one SH-2 when the other hammers SDRAM (see the emulator section)EMU:jgenesis core 0.14.1[T305-1].
  • For debugging, GensKMod or BlastEm. marsdev's skeleton targets GDB tracing in Gens-KMod, BlastEm and UMDKEMU[S061-1]. See Debugging (GDB remote stubs for the SH-2).
  • Test on real hardware. Code has worked in an emulator and failed on a 32XHW[S048-3]; the case is under Pitfalls.

Details#

Kega Fusion#

  • What it runs. Version 3.64 plays Chilly Willy's DMA PWMEMU[S046-2]. Chilly Willy also reports that his devkit examples, Yeti3D and TicTacToe, work on itCOMM[S054-1].
  • Mars Check. TascoDLX, a GenDev forum member, found version 3.61 failing 26 of the 161 tests, in the thread "Mars Check Program results for Kega Fusion v3.61" (2009)EMU[S115-1]. His count for 3.63 is 4 failuresEMU[S115-363]. dilworks, reporting a PicoDrive bug on GitHub (issue 96, 2019), calls 3.63 a clean passEMU[S179-363]; see Test ROMs: Sega's Mars Check Program.
  • Misaligned accesses. ChibiAkumas publishes assembly-language tutorials for many platforms. The SH-2 tutorial on the Chibi Aliens website warns that Fusion accepts misaligned word and longword accesses that fail on a real 32XCOMM[S031-1].
  • Timing. bakemono, a Sega-16 forum member, compares Fusion with a console in the thread "busting 32x performance myths" (2019): it "does not emulate all of this timing nuance"EMU[S025-1].
  • Free-running timer. d32xr is the source code of Doom 32X Resurrection, a homebrew rework of Doom for the 32X, published on GitHub. The message of its commit that adds an FRT profiler says the timer "Doesn't work in Fusion"CODE[S032-1].

Use Fusion 3.64 for a first check of PWM sound and of code that should simply run. Do not trust it for timing, alignment or the free-running timer.

Gens/GS#

  • Stock release 7 fails. Chilly Willy's DMA PWM mod-player ROMs, posted in the GenDev forum thread "MOD Player for 32X - the Good Enough release" (2011), do not work on itEMU[S047-1].
  • His patched build works. He posted a build of release 7 with his DMA PWM fixes in the same threadEMU[S047-3], and the ROMs run on itEMU[S047-2].
  • Interrupt-driven DMA PWM needs one more change on top of those fixesEMU[S046-4].

Use Gens/GS for DMA PWM only in Chilly Willy's patched build.

GensKMod#

  • A Gens build with a GDB server. The SpritesMind page on debugging with GensKMod credits Graz for making it GDB-readyEMU[S227-gr]. That page points to the dev build repository on Bitbucket for version 0.7.3EMU[S227-repo].
  • No 32X DMA in 2009. Graz, developing his own 32X code, wrote in the GenDev forum thread "DMA to PWM" (2009) that he stopped using GensKMod when he found it did not support DMAEMU[S048-6].

Use GensKMod for GDB debugging; the set-up is on Debugging (GDB remote stubs for the SH-2).

BlastEm#

  • A debugger first. BlastEm, from retrodev.com, has an integrated debuggerEMU[S228-dbg] and supports the GDB remote debug protocolEMU[S228-1].
  • marsdev's skeleton lists it for GDB tracingEMU[S061-1]. The sources here give no 32X test of BlastEm.

Use BlastEm for source-level debugging of the Mega Drive side.

ares#

  • A missing 32X layer, fixed. ares is developed on GitHub (ares-emulator/ares). Its issue 744 (2022) reported crackling, a freeze and a missing 32X layer in the Soulstar X prototype; the issue is closedEMU[S083-1].
  • The same bug in another emulator. In a 2023 comment on that issue, fedex81 reports fixing the missing layer in his emulator helios32x by adding a frame-buffer mirrorEMU[S083-2]. The mirror sits at $24040000-$24060000, above the overwrite imageEMU[S083-3].
  • One GDB server. ares has a single global GDB serverEMU[S229-1]. Its issue 2013 (2025) notes that the 32X needs a second server, because the 68000 and the SH-2s cannot share oneEMU[S229-2].

Use ares as a second opinion on how a game displays; for GDB it serves one processor architecture at a time.

jgenesis#

  • Where it lives. jgenesis is developed on GitHub by jsgroth; its issue 493, "[32X] memory benchmark", tracks its SH-2 timingEMU[S084-3].
  • Cached reads run fast. jsgroth traces the gap between jgenesis and the hardware on cached reads to the SH-2 pipelineEMU[S084-3], and leaves the issue openEMU[S084-4].
  • Timers. jgenesis does not emulate the SH-2 free-running timerEMU[S130-1]. Its watchdog timer runs in interval-timer mode onlyEMU[S130-2].
  • Test results. The results of the test ROMs are listed in the emulator section below.

Use jgenesis to check code against the manual's rules. Profile with the watchdog timer, and do not judge bus-contention techniques on it.

PicoDrive#

  • Mars Check stops at test 123. PicoDrive, notaz's emulator on GitHub, aborts at test 123, one of the SH-2 DMA tests, as dilworks reported in PicoDrive issue 96 (2019)EMU[S179-abort].
  • The cause is the test. notaz explains that the test overwrites its own program, and that a real 32X survives because the code stays in the SH-2 cacheCOMM[S179-cache].
  • Not fixed. He would not emulate that for a test ROM, since no game relies on the cache that wayCOMM[S179-wont].

Do not use PicoDrive to check code that depends on what stays in the SH-2 cache.

Pitfalls#

Code works in the emulator and fails on the 32X.

  • In the GenDev thread "DMA to PWM" (December 2009), Chilly Willy's DMA PWM test worked on Fusion, not on Gens/GS and not on real hardwareEMU[S048-12]HW[S048-12].
  • On hardware it behaved as if no DMA requests arrivedHW[S048-13].
  • The cause was a shared variable kept stale in the SH-2 cache. Reading it through the cache-through address (OR 0x20000000) fixed itHW[S048-1].
  • Chilly Willy notes that the emulators were not affectedEMU[S048-2]. The cache-through addresses are on The SH-2 on the 32X.

An emulator's noise can hide your bug.

  • In the same thread (January 2010), the forum member mic_ wrote that Kega 3.51's distorted PWM output made development impossible. A distortion could come from the program or from the emulatorEMU[S048-5].
  • Chilly Willy answered by running his test on a console, off an SD card on a Neo Myth flash cartridgeHW[S048-rh].

Tested on the jgenesis emulator#

These results come from small 32X test ROMs run on the jgenesis 0.14.1 emulation core. Nobody has confirmed them on a real 32X yet.

  • Cache control. Writing CP = 1 purges the cache; writing CP = 0 does notEMU:jgenesis core 0.14.1[T007-1].
  • At application entry, both SH-2s have CCR = $01EMU:jgenesis core 0.14.1[T013-1].
  • The 68000 window at $880000 shows cartridge $000000-$07FFFFEMU:jgenesis core 0.14.1[T024-1].
  • Auto fill. A length register of 3 fills 4 wordsEMU:jgenesis core 0.14.1[T103-1].
  • Frame buffer while FM = 0. An SH-2 write is not held until FM = 1; it is droppedEMU:jgenesis core 0.14.1[T001-1].
  • RV = 1. SH-2 cartridge reads almost stop while the 68000 holds RV = 1, and resume at RV = 0 with no wrong data. That is the "waits" side of the manual (see Cartridge bank switching)EMU:jgenesis core 0.14.1[T110-1].
  • Free-running timer. The counter never movesEMU:jgenesis core 0.14.1[T300-1].
  • Instruction timing. One clock per register instruction and 11 per cache-through SDRAM readEMU:jgenesis core 0.14.1[T302-1].
  • Frame-buffer writes with the FIFO full cost 5, 5 and 10 clocks for byte, word and long writesEMU:jgenesis core 0.14.1[T302-2].
  • No bus contention. The second SH-2 hammering SDRAM does not slow the firstEMU:jgenesis core 0.14.1[T305-1]. A 68000 running from ROM does not slow SH-2 cartridge readsEMU:jgenesis core 0.14.1[T302-3].
  • Mars Check. Sega's Mars Check Program v1.0 runs all 161 tests to its "all finished normally" screen with ERROR COUNT 0EMU:jgenesis core 0.14.1[T028-1].
