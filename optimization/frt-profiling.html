Profile with the SH-2 free-running timer

To find out where a frame spends its time you need a clock that counts SH-2 cycles. The SH-2 has one built in: the free-running timer (FRT), a 16-bit counter that runs on its own. d32xr is the GitHub source of Doom 32X Resurrection, a homebrew rework of Doom for the 32X. This page describes how d32xr used the FRT to profile, how to read it correctly, and the conflict with Sega's rule that programs must not use the FRT.

Use it when you need a cycle-accurate clock to measure where a frame spends its time.

Summary#

  • A profiling clock. d32xr used the master SH-2's free-running timer, counting at SYSCLK/128, with an overflow interrupt to extend it past 16 bitsCODE[S032-tcr][S032-ovf][S032-cnt].
  • Caveat. The 2021 d32xr commit that added it, "Add Free Running Timer implementation", says it does not work in the Kega Fusion emulator and is only useful for profilingCODE[S032-fus].
  • Sega's rule. Sega's manual says programs cannot use the FRT and fixes its settingsDOC[S001-frt]. Whether that set-up is needed is disputed; see Interrupts. Use this technique for measurement builds.
  • The current d32xr no longer does this. Its profiling counter now comes from the watchdog timer (WDT) in interval mode at Fs/4096CODE[S096-wdt][S096-4096].
  • TOCR. Its WDT handler writes TOCR = $E2CODE[S096-tocr], the value Sega's FRT set-up requiresDOC[S001-e2]. The FRT stays with Sega's set-up, and the WDT does the timing.

Details#

Registers#

RegisterAddressSizeSource
FTCSR (control and status)$FFFFFE118DOC[S003-ftcsr]
FRC H / FRC L (the 16-bit counter)$FFFFFE12 / $FFFFFE138 + 8DOC[S003-frch]DOC[S003-frcl]
TCR (clock select in bits 1-0)$FFFFFE168DOC[S003-tcr]

TCR's clock select: 00 = phi/8, 01 = phi/32, 10 = phi/128, 11 = external clockDOC[S003-cks8]DOC[S003-cks128]. d32xr writes TCR = 2, the phi/128 settingCODE[S032-tcr].

What the commit does#

d32xr's commit "Add Free Running Timer implementation" adds an FRT-based timer for profilingCODE[S032-subj].

  • It converts counts to milliseconds with 128.0f * 1000.0f divided by the clock rate of the SH-2CODE[S032-conv].
  • It uses 23011360 Hz (NTSC) or 22801467 Hz (PAL)CODE[S032-hz].

Mechanism#

  • FRC is a 16-bit up-counter. On overflow ($FFFF to $0000) it sets OVF in FTCSRDOC[S003-ovf].
  • The CPU reaches FRC through an 8-bit TEMP register: read the upper byte first, then the lowerDOC[S003-temp]DOC[S003-order].
  • Reading the upper byte copies the lower byte into TEMP at the same moment, and the lower-byte read returns TEMPDOC[S005-temp]. That is why the order matters: the two halves then come from one instant.
  • d32xr counts overflows in its FRT interrupt handler and combines them with FRC into one count: the overflow count shifted left 16 bits, ORed with FRCCODE[S032-cnt].
  • One count at phi/128 is 128 SH-2 clocks: 128 / 23.01136 MHz = about 5.56 microseconds (NTSC)DERIVED[S011-clk].

Cost and conditions#

  • The timer interrupt runs at priority 14 in d32xrCODE[S032-pri].
  • Sega's bulletin 10: the FRT must be initialised whether or not interrupts are usedDOC[S076-b10].
  • It does not run in FusionCODE[S032-fus].

The current d32xr: the watchdog timer#

In the current d32xr:

  • I_GetFRTCounter returns the watchdog countCODE[S096-wdt].
  • The debug overlay prints per-stage times in milliseconds (BSP, wall segments, planes, sprites, total) from that counterCODE[S096-overlay].
  • The WDT is in interval-timer mode, which Sega does not forbid. Sega forbids a watchdog internal reset, a different modeDOC[S001-wdt].

Measured gain#

This is a measuring tool, so it has no gain of its own.

Code example#

Example: time a routine with the SH-2's free-running timer (FRT). The FRT counter FRC is a 16-bit register at $FFFFFE12 (high byte) and $FFFFFE13 (low byte). It is read a byte at a time, and the high byte must be read first. Reading it latches the low byte in a temporary register, and the second read returns that latched value, so the two halves come from the same instant. The code is SH-2 assembly for GNU as and leaves the count in r2.

        mov.l   frc_h,r1        ! r1 = $FFFFFE12, address of FRC high byte
        mov.b   @r1,r2          ! read FRC high first; the low byte is latched
        mov.b   @(1,r1),r0      ! read FRC low, the latched value, into r0
        extu.b  r2,r2           ! clear the sign extension of the high byte
        extu.b  r0,r0           ! clear the sign extension of the low byte
        shll8   r2              ! move the high byte up
        or      r0,r2           ! r2 = the 16-bit counter value
        ...
        .align  2
frc_h:  .long   0xFFFFFE12

To time a routine, run this code before and after it and subtract the two counts. The result is in FRT ticks, and it wraps after 65536 ticks. Notice that a byte read sign-extends, which is why each half goes through extu.b before they are combined.

When it does not help#

  • Emulators that do not model the FRT. The commit reports Fusion among themCODE[S032-fus].
  • Release builds bound by Sega's FRT rulesDOC[S001-frt].

Pitfalls#

A counter read in the wrong order returns a torn value. FRC H must be read before FRC LDOC[S003-order]. Read the low byte first and you get the low byte left in TEMP by an earlier read.

  • d32xr's 2021 commit reads both inside one C expressionCODE[S032-read].
  • Reading FRC H into its own variable first, then FRC L, keeps the order the manual asks forDOC[S003-order].

A word write to FTCSR is an address error. FTCSR is a byte register at an odd addressDOC[S003-ftcsr]. A word access to an odd address raises an address errorDOC[S003-wodd]. Clear it with a byte store.

  • The 2021 commit's handler clears it with a word write to $FFFFFE11CODE[S032-movw]CODE[S032-addr].
  • The current d32xr has no FRT overflow handler at all. Its start-up code writes the same register the safe way, with a byte store at offset 1 of the FRT blockCODE[S184-tcsr].
