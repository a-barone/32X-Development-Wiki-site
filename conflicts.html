Where sources disagree

This page lists every fact on which two sources disagree, grouped by the page that uses it. Each entry gives both sides with a short quote and the kind of evidence behind it, then says whether the question is still open or what settled it.

"The 32X Hardware Manual" is Sega's hardware manual as kept in the 32XDK repository on GitHub. An entry calls it the 32XDK edition only where it also cites Sega's original R4 manual (July 1994), so that the two can be told apart.

Cartridge bank switching#

  • When the 68000 holds RV = 1, does an SH-2 cartridge access wait, or can it hang?
    • One side:DOC The 32X Hardware Manual, section 3.2 "DREQ Control Register": "The SH2 side cannot access the ROM when RV = 1." and it "Waits until value becomes 0".
    • The other side:COMM The "Bank switching" page of the 32XDK wiki: under some circumstances the SH-2 "can hang/crash when it accesses the cart when RV is set".
    • Status: open: on the jgenesis emulator an SH-2 cartridge read loop almost stops while RV = 1 (10 to 12 reads against 1,290) and resumes at RV = 0 with no wrong data, which is the waits side; nobody has tested it on a console.
  • Does writing to cartridge save RAM depend on the RV bit?
    • One side:DOC Sega's Technical Bulletin #7 "RV bit value when using FRAM or SRAM" (23 September 1994): "The RV bit is irrelevant when reading and writing to the SRAM."
    • The other side: It does: with RV = 0, writes to most save RAM fail.
    • HW Charles MacDonald, a GenDev forum member, traced the cartridge signals in the thread "Some 32X cart port questions" (October 2012): "When RV=0 you can't write to most cartridge save RAM or the Sega CD Backup RAM cartridge" (LWR# is never asserted with RV = 0).
    • CODE Chilly Willy, author of Wolf32X and of a 32X devkit, posted working save-RAM code in the GenDev forum thread "Accessing SRAM". It sets RV = 1 around each access and uses odd bytes only.
    • Status: open: Charles MacDonald traced the signals on a console, but the bulletin does not say how its SRAM is wired.

Boot, security and ROM headers#

  • Where does the 32X user header end in the cartridge: at $3ED or at $3F0?
    • One side:DOC The 32X Hardware Manual (32XDK edition), section 5.1 "Initial Data Load", says "Address 3C0h to 3EDh of the ROM cartridge is called" the user header.
    • The other side: At $3F0.
    • DOC In Sega's original R4 manual, page 80, "3EDh" is struck through and "3F0h" is written next to it.
    • CODE The start-up file of marsdev, andwn's 32X devkit, follows a header of the same shape (a 16-character name and 8 long words) directly with the 68000 code: "! Standard MD startup code at 0x3F0".
    • Status: resolved: Sega corrected its own text in the R4 manual.

Bus arbitration#

  • With RV = 1, does a ROM-to-VRAM DMA read the cartridge bytes at $1070-$1073 correctly?
    • One side:DOC Sega's Technical Bulletin #12 "ROM & RV bit = 1": "The following address data is not normally read when RV=1."
    • The other side:CODE Sega's own Mars Check program runs its RV = 1 DMA test from work RAM, copies cartridge ROM $000400-$0013FF and compares every byte, $1070-$1073 included.
    • Status: open: nobody describes a measurement of those bytes. TascoDLX, a GenDev forum member, relays (2009) that the program has been reported to pass on a real 32X, and dilworks repeats it in a comment on issue #96 of the PicoDrive emulator's GitHub repository (2019).

DMA (68000 to SH-2 FIFO, SH-2 DMAC)#

  • Is the 16-byte transfer unit of the SH-2 DMA controller legal on the 32X?
    • One side: It is illegal, says TascoDLX in the GenDev forum thread "Mars Check Program results for Kega Fusion v3.61" (2009).
    • COMM TascoDLX says Mars Check tests 127, 128 and 133 get it wrong: "This test incorrectly sets the DMA transfer unit to 16-byte".
    • COMM TascoDLX calls it "an illegal setting because it requires longword access,".
    • The other side: It is legal, and Sega's own test program uses it.
    • COMM Snake, another GenDev forum member, answers TascoDLX in the same thread: "None of the modes are illegal, and they all work as documented."
    • DOC Hitachi's SH7604 manual documents the 16-byte unit (TS = 11), and the 32X Hardware Manual does not restrict TS.
    • CODE Sega's Mars Check program loads CHCR0 = $5EE1 (16-byte unit, auto-request) in its ROM-to-frame-buffer and SDRAM-to-frame-buffer DMA routines (tests 129 to 132). It uses the unit on purpose in more than one test.
    • Status: open: nobody describes a test of the 16-byte unit itself; the reports that the whole program passes on a real 32X are under Bus arbitration.
  • Does the SH-2 DMA-end interrupt (CHCR IE bit, VCRDMA vector) fire on a real 32X?
    • One side:HW ob1, a GenDev forum member, in the thread "DMA DEI" (May 2021): "I've done the same test on real PAL hardware, and it doesn't seem to work either".
    • The other side: It works on real hardware, say Chilly Willy and Vic.
    • CODE Chilly Willy's player in the GenDev forum thread "Interrupt driven DMA PWM audio" (2012) sets CHCR1 = 0x18E5, commented "intr enabled".
    • COMM Chilly Willy writes in that thread: "It works on real hardware and on Fusion 3.64".
    • COMM Vic, who maintains d32xr (the Doom 32X Resurrection source on GitHub), wrote in the GenDev thread "DMA DEI" (2024): "so we do know that setting the 2-nd bitflag in CHCR works on real hardware".
    • Status: open.

Interrupts#

  • Do retail 32X units need Sega's free-running-timer set-up and the FRT-toggling interrupt handler?
    • One side: Sega says the set-up is required.
    • DOC The 32X Hardware Manual, section 5.3, says "The SH2 internal free-run-time (FRT) cannot be used with programs."
    • DOC Sega's Technical Bulletin #10 (September 1994) says "Initialization of the free run timer must be done".
    • DOC Sega's Technical Bulletin #27 (December 1994) warns that "an interrupt of the same level may be acknowledged twice consecutively".
    • DOC Sega's Hardware Manual Supplement 2 is the July 1994 correction sheet on this bug. On page 8 it says corrective action must be taken "because an unmodified chip is used in the initial version of the actual device".
    • COMM Chilly Willy, in the GenDev forum thread "simplest method for 32x sound?" (2025), writes "Certain SH2 chips had a bug that made it lose interrupts". He adds that d32xr has the fix and his older code does not.
    • The other side: Two members of the GenDev forum doubt that it is needed. Both posted in the thread "DMA to PWM" (January 2010).
    • COMM Chilly Willy left the set-up out of his Wolf32X port: "I didn't bother in Wolf32X and no one has complained".
    • COMM Snake replied that the workaround was meant for a lock-up after the reset button and that it fails: "Only problem being that the workaround doesn't help in the slightest".
    • Status: open: neither side describes a test on a console.
  • Which SH-2 cut has the 32X interrupt problem, and which cut did the first 32X units use?
    • One side: Community sources name the cut the first units used.
    • COMM The "Bugs and quirks" page of the 32XDK wiki, quoting Toshiyasu Morita's FAQ, says "early revisions of the 32x use the 2.5 cut of the SH2", the cut with the problem.
    • COMM TMorita, a GenDev forum member, recalled from memory in the thread "32X overclocking" (2008): "The 32x originally shipped with the FC3 version of the SH2,".
    • The other side: Sega says cut 2.5 is the corrected chip.
    • DOC Sega's Hardware Manual Supplement 2, page 8, says "With the EVA chip cut 2.5, operation is normal although no corrective action is taken", and that the first production units use an unmodified chip.
    • Status: open.
  • Which FRT start values does Sega's interrupt fix use: TIER 01h with OCRA 0002h, or TIER 00 with OCRA 0001?
    • One side:DOC The 32X Hardware Manual (32XDK edition), section 5.3 rule 2 (page 87 of the R4 original): TIER 01h, OCRA 0002h, FTCSR 01h, TOCR E2h.
    • The other side: TIER 00 with OCRA 0001.
    • DOC The sample program in Sega's Hardware Manual Supplement 2 (6 July 1994), page 13: TIER 00, output compare register A 0001, TCSR 1, TOCR E2.
    • CODE Sega's Mars Check program sets TIER 0 and OCRA 0001.
    • CODE d32xr's SH-2 start-up code also sets OCRA = 1.
    • Status: open: both are Sega documents and no test on a console compares them; TOCR and its flip agree.

Memory map#

  • Is there a bank set register at $A130F0 on the 68000 side?
    • One side:DOC The 32X Hardware Manual (32XDK edition), section 3.1, lists "A1 30F0h" as "Bank Set Register" in its memory map for ADEN = 1.
    • The other side: $A130F0 belongs to the Mega Drive, not the 32X.
    • DOC Sega's original R4 manual, page 16, says the Mega Drive "has a bank set register (A1 30F1h - A1 30FFh odd numbered addresses)".
    • DOC Figure 3.1 of the R4 manual, page 15, labels $A130F0 "See MD Manual".
    • DOC The 32X's own bank set register is at $A15104, in section 3.2.1 of the 32XDK edition.
    • Status: resolved: $A130F0 belongs to the Mega Drive's own bank set registers, as Sega's R4 manual shows on pages 15 and 16; the 32XDK copy's map row is wrong.
  • Where does the fixed cartridge window at 68000 $880000 end: at cartridge $7FFFFF or at $07FFFF?
    • One side: At cartridge $7FFFFF.
    • DOC Sega's original R4 manual, page 16, says the window is made by "fixing 00 0000h - 7F FFFFh (4Mbit) of the cartridge ROM".
    • DOC The 32XDK edition, section 3.1, copies the sentence.
    • The other side: At cartridge $07FFFF.
    • DOC Figure 3.1 of the R4 manual, page 15, shows "ROM Cartridge 0000 0000h 0007 FFFFh".
    • DOC Sega's US hardware manual, page 14, prints "880000H - 8FFFFFH is allocated by fixing 000000H - 07FFFFH (4 Mbit)".
    • DOC The ROM access table of the 32XDK edition, section 3.5, maps 88 0000h - 8F FFFFh to cartridge 00 0000h - 07 FFFFh.
    • Status: open: the "(4Mbit)" in the page-16 sentence is the size of the second range, which points to a misprint, but no test on a console or released code settles it.
  • What does the 68000 see at $000000 at power-on, with ADEN = 0?
    • One side:DOC The 32X Hardware Manual (32XDK edition), section 3.1, lists "Custom internal ROM Vector ROM" at 000000h in its table for ADEN = 0.
    • The other side:DOC Figure 3.1 of Sega's original R4 manual, page 15, shows "When Power is on (ADEN = 0) 00 0000h ROM Cartridge". Sega's US hardware manual has the same figure.
    • Status: resolved: the 68000 sees cartridge ROM at $000000, as Sega's figure shows, with the system registers at $A15100; the 32XDK copy's table is wrong.
  • Does an SH-2 access to the 32X VDP area while FM = 0 get dropped, or does it wait?
    • One side:DOC In its memory-map chapter, section 3.1, the 32X Hardware Manual has reads undefined and writes ignored while FM is 0.
    • The other side:DOC In its access-competition section, 3.4, the same manual has the SH-2 wait until FM becomes 1.
    • Status: open: the entry under Frame buffer and line table quotes both passages.

Auto fill (VDP frame buffer fill)#

  • Does the auto fill length register take the word count, or the word count minus 1?
    • One side:DOC Sega's original R4 manual, page 38: "set the value for the to-be-filled word length (0~255)."
    • The other side: The word count minus 1.
    • DOC The 32X Hardware Manual (32XDK edition), section 3.2.3, and Sega's US hardware manual, page 38, both say "the to-be-filled word length - 1".
    • COMM The "Video" page of the 32XDK wiki gives "a max length of 256 words", which fits count - 1.
    • CODE Sega's Mars Check program writes $FF to the length register and then checks 256 words.
    • Status: resolved: the register takes the word count minus 1. Sega's own test program uses it, and the program is reported to pass on a real 32X (see the Bus arbitration entry).

Frame buffer and line table#

  • While FM = 0, are SH-2 accesses to the frame buffer, VDP registers and palette ignored, or held until FM = 1?
    • One side:DOC The 32X Hardware Manual, section 3.1 "32X VDP Access", says that when "the FM bit is 0, read is undefined and write is ignored."
    • The other side:DOC The same manual, section 3.4 "VDP Access Competition", says the SH-2 "waits until the FM bit (interrupt mask register bit 15) is 1".
    • Status: open: the same disagreement is listed under Memory map.
  • Can the SH-2 DMA controller write the frame buffer?
    • One side:COMM Chilly Willy, in the GenDev forum thread "Super VDP" (2009), relays: "According to the SEGA docs, you can't use the SH2 DMA on the framebuffer."
    • The other side: It can.
    • COMM Snake, a GenDev forum member, says in the same "Super VDP" thread (2009) that it works but gains nothing: "DMA is a complete waste of time. It's no faster than the CPU at best,".
    • CODE Sega's own Mars Check program DMAs into the frame buffer in tests 129 to 132.
    • Status: open: the 32X Hardware Manual does not state the ban, and nobody has measured the speed.

Video modes (packed pixel, direct colour, run-length)#

  • Which bits of the bitmap mode register hold PRI and the 240-line flag?
    • One side:DOC The register table in the 32XDK copy of the 32X Hardware Manual, section 3.2.3, puts PRI at bit 13 and 240 at bit 7.
    • The other side:DOC Sega's original R4 manual, page 36, prints the register row as PAL, seven unused bits, then "PRI 240", four unused bits, "M1 M0": PRI is bit 7 and 240 is bit 6.
    • Status: resolved: PRI is bit 7 and 240 is bit 6, as Sega's R4 manual prints the register; the bit numbers in the 32XDK copy are wrong.
  • Does setting the 240-line bit in NTSC mode cause VDP errors?
    • One side:DOC The 32X Hardware Manual, section 3.3, warns that with the "240 bits when in the NTSC mode VDP will have operating errors".
    • The other side:EMU:jgenesis core 0.14.1 A test ROM on the jgenesis emulator keeps the 240 bit as written (read-back $8041) and shows a normal 320 x 224 frame.
    • Status: open: an emulator result does not answer a hardware question; this needs a test on a console.

Mega Drive sound and 32X PWM together#

  • Can the 68000 or the Z80 reach the PWM registers?
    • One side:COMM TMorita, early in the GenDev forum thread "Super VDP" (2008): "I don't think the 32x PWM is accessible from the 68000/Z80 side".
    • The other side: They can, after a bank switch.
    • DOC The 32X Hardware Manual, section 3.4, says the PWM registers can "be accessed from the 68000 or Z80" after a bank switch.
    • COMM Chilly Willy, later in the same "Super VDP" thread: "The 32X PWM is indeed accessible from the 68K side (at 0xA15130 - 0xA15139)."
    • Status: resolved: Sega's manual says yes, and the later forum post corrects the early claim.

PWM sound (registers, cycle, FIFO)#

  • Is the PWM cycle (and the pulse width) the register value times Scyc, or the value minus 1 times Scyc?
    • One side: The register value times Scyc.
    • DOC The 32X Hardware Manual (32XDK edition), section 3.2.1, says "set value × Scyc becomes the cycle".
    • DOC The same section says "The value set by bit 11-0 × Scyc becomes the pulse width." Sega's US hardware manual prints the same pulse-width sentence.
    • COMM Graz, a GenDev forum member, in the thread "DMA to PWM" (2009), computes "Cycle Register becomes 23.01 x 10^6 / 22050 = 1044."
    • The other side: The register value minus 1, times Scyc.
    • DOC Sega's original R4 manual, page 59, says "sampling rate with the set value –1 as a multiple of".
    • DOC Page 59 of the R4 manual also says "the set value – 1 is the height, when 1 is set,".
    • DOC Sega's US manual, page 59, also has "with the set value - 1".
    • COMM Chilly Willy gives the same rule in the GenDev forum thread "32X Audio" (2008): "Sample period is SH clk / (cycle count - 1)".
    • COMM Chilly Willy repeats it in the GenDev thread "DMA to PWM" (2009): "The rate is (NTSC) 23.01 MHz / (count - 1)."
    • CODE Chilly Willy's player in the Sonic Retro forum thread "Interrupt-Driven DMA PWM on the 32X" (2012) adds 1 to the cycle: "(((23011361 << 1)/SAMPLE_RATE + 1) >> 1) + 1; // for NTSC".
    • Status: open: Sega's manuals print both readings, nothing has been measured, and the manual's example of 1047 for about 22 kHz fits either reading.
  • Does an SH-2 interrupt that is not cleared keep occurring, or stop occurring?
    • One side:DOC The 32X Hardware Manual, section 3.2.2 "Interrupt Sources and Priority Levels": "Interrupt continues indefinitely until cleared."
    • The other side:DOC The same manual, section 3.2.2 "PWM Interrupt Clear Register": "If not cleared, interrupt will no longer occur."
    • Status: open: the same question applies to the CMD and VRES interrupts on the Interrupts page.
  • Does PWM control LMD = 01 send the left channel to the left output or to the right?
    • One side: 01 means left.
    • DOC Sega's original R4 manual, page 26, lists the LMD settings 00 to 11 as "OFF L R Setting not allowed", so 01 = L.
    • CODE Chilly Willy's player in the Sonic Retro forum thread "Interrupt-Driven DMA PWM on the 32X" writes $0185 with the comment "RMD = right, LMD = left".
    • The other side: 01 means right.
    • DOC Sega's Genesis 32X US Overview, page 39, gives 01 = R and 10 = L in its left-mode table, with bit 4 as MONO.
    • COMM Chilly Willy's own register list in the GenDev forum thread "32X Audio" says "Left mode = 00 = off, 01 = Right channel,".
    • Status: open: only a test on a console of which speaker LMD = 01 drives settles it.
  • What is the smallest usable PWM pulse-width value: 1 or 2?
    • One side:DOC Sega's original R4 manual, page 59: "the set value – 1 is the height, when 1 is set,".COMM Chilly Willy, in the GenDev forum thread "DMA to PWM" (2009): "So 1 will be the minimum PWM sample value,".
    • The other side: 2 is the minimum.
    • COMM mic, a Sega-16 forum member and author of the Lusid Dreams music player, in the thread "32X mod player": "The minimum allowed sample value is (AFAIK) always 2."
    • CODE Chilly Willy's player settings in the GenDev forum thread "32X Audio" use "#define SAMPLE_MIN 2".
    • Status: open: nobody has measured the output at a value of 1.
  • May the SH-2 write the PWM pulse-width registers with byte accesses?
    • One side:DOC Sega's original R4 manual (July 1994), page 58: "Since any register can be accessed in bytes, the MEGA Drive side can switch banks".
    • The other side:DOC Sega's Technical Bulletin #19 "PWM registers" (23 September 1994) forbids byte access from the SH-2 to the left, right and mono pulse-width registers ($20004034, $20004036, $20004038): "The byte unit-based access is prohibited."
    • Status: superseded: the later bulletin replaces the manual's rule for these three registers.

The SH-2 on the 32X#

  • Does a full SH-2 cache purge take a write of 1 or of 0 to CCR bit 4 (CP)?
    • One side: Writing 1 purges the cache.
    • DOC Hitachi's SH7604 hardware manual, section 8.2, says "When 1 is written to CP, all cache entries" are purged (also sections 8.5.1 and 8.5.2).
    • DOC The 32X manual, page 66, also says 1 is written to the CP bit.
    • The other side: Writing 0 purges the cache.
    • DOC Hitachi's SH7604 hardware manual, section 8.4.6, says a purge of the "entire cache area can only be carried out by writing 0" to CP.
    • DOC Hitachi's original manual has the same sentence.
    • Status: resolved: shipped code writes 1; d32xr's start-up code purges with CCR = $10, then $11.
  • Does an SH-2 on-chip register access wait while the other bus master holds the external bus?
    • One side:DOC Hitachi's SH7604 hardware manual, section 7: "on-chip peripheral modules can operate in parallel to the external bus." (unless a user-break bus monitor is set).
    • The other side: It waits.
    • DOC Sega's Technical Bulletin #32 "SH2 Internal I/O Register Access Cycles", page 1: "Internal I/O access occurs after the bus master completes the use of the bus."
    • COMM The "SH2 on the 32X" page of the 32XDK wiki repeats the bulletin's rule.
    • Status: open.
  • How long can one SH-2 cartridge ROM access take?
    • One side:DOC The 32X Hardware Manual, section 4.1, gives an SH-2 read or write "6 wait (min) ~ 15 wait (max)" on top of a minimum bus cycle of 2 clocks.
    • The other side:COMM bakemono, a Sega-16 forum member, in the thread "busting 32x performance myths" (2019), recalling the documents ("IIRC"): "access time could be extended from 8 up to 18 clocks."
    • Status: open.
  • May an application put an SH-2 to sleep with the SLEEP instruction?
    • One side:DOC The 32X Hardware Manual, section 5.3: "Do not use the sleep command in an application."
    • The other side: It can, and the boot ROM does.
    • COMM Chilly Willy, in the GenDev forum thread "Using 32x as a 3rd plane, possible?" (April 2019): "SLEEP puts the SH2 in power down mode until an (enabled) interrupt".
    • COMM Chilly Willy adds in that thread: "be sure you put the routine that sleeps in sdram".
    • CODE The master SH-2 boot ROM, disassembled in the GenDev forum thread "Master SH2 BIOS", itself writes $9F to SBYCR and sleeps.
    • Status: open.

Wide frame-buffer writes#

  • For pushing pixels to the frame buffer, do two SH-2s help, or is one faster?
    • One side:COMM Snake, in the GenDev forum thread "Super VDP" (2009): the only way to "hit that 5 cycle per pixel limit is using both CPUs."
    • The other side:COMM Mask of Destiny, another GenDev forum member, earlier in the same "Super VDP" thread (2007): it may be "faster to just use one SH-2 and halt the other one." (or to have them take alternate lines).
    • Status: open.

Devkits (Chilly Willy's devkit, marsdev)#

  • At which cartridge offset does the 68000 initial program (the security code) start: $3F0 or $3FA?
    • One side: At $3FA.
    • DOC The 32X Hardware Manual (32XDK edition), section 3.1 "MEGA Drive Memory Map", says the program "is laid out in cartridge ROM at 3FAh or more".
    • DOC Sega's original R4 manual has the same words.
    • The other side: At $3F0.
    • DOC Section 5.2 "Security" of the 32X Hardware Manual says it "must begin from the start of the program (address 3F0h) without change".
    • DOC The R4 original agrees.
    • CODE marsdev's 32x-skeleton places the 68000 code at $3F0: "! Standard MD startup code at 0x3F0".
    • Status: open: both readings are in Sega's original R4 manual, so the manual contradicts itself; released code uses $3F0.

Test ROMs: Sega's Mars Check Program#

  • How many Mars Check tests does Kega Fusion 3.63 fail?
    • One side:EMU TascoDLX, in the GenDev forum thread "Mars Check Program results for Kega Fusion v3.61" (October 2009): "Fusion v3.63 fails 4 of 161 tests".
    • The other side:EMU dilworks, commenting on issue #96 of the PicoDrive emulator's GitHub repository (2019): "Kega Fusion gets a clean pass as of version 3.63."
    • Status: open: both are emulator reports.

32x-playground (gameblabla)#

  • What is 68000 $A130F1: an SRAM control register, or a bank set register?
    • One side:DOC Sega's original R4 manual, section 3.1: "bank set register (A1 30F1h - A1 30FFh odd numbered addresses)"; its sample AllBankSet writes 8 registers from $A130F1.
    • The other side:CODE The 68000 code of gameblabla's 32x-playground uses it as SRAM control: "move.b #1,0xA130F1 / SRAM enabled, write enabled /".
    • Status: open: the two may describe different cartridge hardware, and neither source names the cartridge.
